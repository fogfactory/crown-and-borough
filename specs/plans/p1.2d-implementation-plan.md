# Plan P1.2d — Géométrie, frontières et graphe (rendu carte v2)

Brief d'exécution autonome pour un modèle d'implémentation.

## Contexte

P1.2a (vocabulaire), P1.2b (villages) et P1.2c (nommage communes) sont faits. Le prompt
source est `specs/prompts/p1.2d-geometrie-graphe.md` — le lire en entier avant de commencer.
État actuel : `internal/engine/mapgen` (raster 256×160, polygones par chaînage de boucles,
graphe avec routes, config 1000×700 / 64 sites), `cmd/server` (génération unique au démarrage,
`api.MapHandler` sert des bytes figés), front `MapViewer` (arcs pointillés centroïde→centroïde).
Références : `specs/gdd.md` §3 (Graphe franchissable), `specs/roadmap.md` (P1.2 détaillé),
`specs/architecture.md` (contrat map.json).

Décisions actées par P1.2d :

- PLUS AUCUN territoire en bord de carte : anneau de sites « cadre » sacrifiés + re-ancrage
  avec padding.
- Frontières DROITES + léger bruit : simplification de chaîne (Douglas-Peucker calibré) +
  jitter déterministe, cohérents des deux côtés de chaque frontière partagée.
- Le système de routes est SUPPRIMÉ (cause du bug visuel MBJL/RVBE : adjacents sans frontière
  commune). Modèle cible : **l'arc géométrique est l'entité de première classe** — toute paire
  de territoires intérieurs partageant ≥ `minSharedEdges` arêtes de grille est un arc, qualifié
  **franchissable** (`adjacencies`) ou **infranchissable** (`impassable`, nouveau champ du
  contrat map.json). Un arc n'est jamais supprimé, seulement requalifié. Futur (hors scope) :
  qualificatif `route` supportant ponts/cols (rendre franchissable un arc infranchissable).
- Degrés contraints par terrain sur le graphe franchissable : min 2 partout ; max :
  mountain 3, swamp 3, hill 3, plain 5, forest 5.
- Taille : `TerritoriesPerPlayer = 8` ; endpoint dev `GET /api/map?players=N` (défaut 4,
  bornes 2..5) → `SiteCount = 8 × players`, `VillageCount = players + 1` ; génération à la
  demande avec cache mémoire (clé = seed + players).
- Front : les arcs centroïde→centroïde disparaissent ; les frontières partagées sont
  dessinées (trait fin pointillé = franchissable, trait épais continu = infranchissable).

Règles absolues :

- Code exclusivement en anglais ; seules les chaînes de contenu de jeu (noms, légende) sont
  en français.
- Stdlib uniquement (pas de lib Voronoï).
- Déterminisme strict : `Generate` est une fonction pure de `(seed, assets, cfg)` — aucune
  horloge, aucun aléa non seedé, aucune itération de map Go dans un ordre non trié (slices ou
  clés triées). Même seed → carte identique byte-for-byte (les champs `[]` vides sont émis
  `[]`, jamais `null`).
- Ne rien commiter. Ne pas modifier `internal/models`. `specs/prompts/p1.2-generation-carte.md`
  et `p1.2-implementation-plan.md` restent tels quels (historique).
- Fichiers prompts `p2.2`/`p2.3` : NE PAS modifier (à réviser lors de leur exécution — coûts
  « route » obsolètes) ; le signaler dans la réponse finale.

## Difficulté et modèle recommandé

Difficulté **4/5** : extraction de chaînes de frontière partagées entre jonctions, cohérence
des sommets simplifiés/jitterés des deux côtés, invariant de graphe (connexité + degré
∈ [2, max(terrain)]), déterminisme byte-for-byte. Modèle à fort raisonnement conseillé
(Claude Sonnet/Opus, GPT-5-class, ou K2-thinking) — un modèle budget risque de boucler sur les
jonctions triples et la cohérence des sommets partagés.

## Décisions de conception (à appliquer et documenter dans le code)

1. **RNG par phase** : `newRNG(seed, phase)` existant (`sha256(seed|phase)` → PCG). Phases :
   `"sites"`, `"terrain"`, `"frontiers"`, `"village"`, `"naming"`, `"jitter"` (la phase jitter
   ne sert qu'à dériver les hash par sommet, cf. 8).
2. **Sites intérieurs + anneau cadre** (`sites.go`) : les `SiteCount` premiers sites sont les
   territoires intérieurs, indices `0..SiteCount-1`, placés par grille jitterée existante
   **confinée à la boîte** `[margin, W-margin] × [margin, H-margin]` avec
   `margin = round(0.08 × min(Width, Height))` (documenté : ≈ 56 px @1000×700). Puis l'anneau
   cadre : marche du périmètre du viewport inset de `margin/2`, espacement
   `spacing = margin`, jitter tangentiel seedé ±0,25×spacing (clampé dans la bande
   `[margin/4, 3×margin/4]`), sites apposés à la suite. Justification dimensionnelle (à
   documenter) : tout point du bord doit être plus proche d'un site cadre que de tout site
   intérieur — avec des sites intérieurs à ≥ margin du bord et des sites cadre à margin/2,
   le pire cas (point à mi-chemin de deux sites cadre, espacement jitteré ≤ 1,5×margin) donne
   `sqrt((0.75×margin)² + (0.5×margin)²) ≈ 0.90×margin < margin` ; marge de sécurité incluse
   dans `spacing = margin` (requis : espacement efficace < √3×margin). Verrou par test
   (`TestFrameAbsorbsBorder`).
3. **Raster et absorption** (`raster.go`) : `assignRaster` inchangé (tous les sites, intérieurs
   et cadre confondus, sur TOUT le viewport). `rasterHasEveryRegion` : strict sur les sites
   intérieurs (erreur explicite si un intérieur n'a aucune cellule), tolérant sur le cadre (un
   site cadre vide est inoffensif). `extractAdjacency(grid, interiorCount)` → uniquement les
   paires intérieur-intérieur partageant ≥ `minSharedEdges = 3` arêtes de grille (seuil
   existant, documenté) : c'est **l'ensemble des arcs**.
4. **Chaînes de frontière partagées** (`frontier.go`, nouveau) :
   - Jonction : sommet de grille dont les cellules incidentes (scan 2×2) portent ≥ 3 owners
     distincts. Les contacts diagonaux (2 owners, 4 segments) ne sont PAS des jonctions — la
     clé canonique de chaîne garantit la cohérence de part et d'autre.
   - Extraction : réutiliser le chaînage existant (`chainLoops`/`traceLoop`, règle main droite)
     pour obtenir la boucle de chaque owner (cadre compris), découper chaque boucle aux
     jonctions en sous-chaînes.
   - Chaîne canonique : clé `(ownerMin, ownerMax, jonctionA, jonctionB)` (en Voronoï, une seule
     frontière par paire de sites entre deux jonctions données ; les chaînes intérieur↔cadre
     sont stockées une seule fois — le polygone cadre est jeté). Traitement UNE fois par chaîne
     canonique : Douglas-Peucker (tolérance 3,5 cellules de grille, espace grille — invariant à
     l'échelle ; départage déterministe : plus petit indice d'écart maximal) → filtre
     anti-escalier → mise à l'échelle viewport (arrondi `math.Round`) → jitter → arrondi int.
   - Filtre anti-escalier (critère documenté, N = 2 cellules de grille) : après DP, tout
     sommet intérieur de chaîne créant un segment < N cellules avec le sommet précédent gardé
     est supprimé, sauf si le segment est incident à une jonction (position imposée par le
     raster). Test : 0 violation sur toutes les chaînes, tous les seeds.
   - Jitter : appliqué une seule fois par sommet de chaîne (jonctions comprises), déterministe
     et cohérent par construction (chaîne stockée une fois). Amplitude ≤ 1 % de la diagonale du
     viewport (≈ 12 px @1000×700) ; réduire à 0,75 % si des micro-croisements apparaissent
     (validité des polygones testée). Les deux côtés d'une frontière partagée réutilisent la
     même chaîne simplifiée/jitterée → sommets EXACTEMENT identiques des deux côtés.
   - Assemblage : concaténation orientée des chaînes par owner intérieur (dédup des jonctions
     aux coutures, suppression des doublons consécutifs, correction d'orientation signe d'aire
     — logique de `simplifyPolygon` conservée). Centroïde = moyenne des sommets du polygone
     final.
   - Re-ancrage : bbox des polygones intérieurs `(minX, minY, maxX, maxY)` → translation
     `minX → padding`, `minY → padding` avec `padding = round(0.02 × hypot(Width, Height))`
     (≈ 24 px @1000×700). Taille finale de la carte = `maxX' + padding, maxY' + padding`
     (documentée dans le code ; NON transportée par map.json — le front la déduit des points,
     marges symétriques, cf. 10). Ordre : jitter AVANT bbox/translation → la contrainte
     « aucun point à moins du padding du bord » est satisfaite par construction.
   - `validateGeometry(polygons, padding)` : ≥ 3 points, aire > 0, tout point ≥ padding
     (bornes = bbox + padding ; plus de bornes Width/Height fixes).
5. **Graphe sans routes, arcs qualifiés, degrés contraints** (`graph.go`) :
   - SUPPRIMER : `repairGraph`, `repairGraphWithGeometry`, `closestAcrossComponents`,
     `closestRouteTarget` (et leurs tests). Aucune arête non géométrique ne peut plus exister.
   - `pruneFrontiers(rng, arcs, terrain)` : itère les arcs en ordre trié, un tirage par arc ;
     déclassement franchissable→infranchissable si probabilité ET gardes : l'arc n'est pas un
     pont du sous-graphe franchissable (BFS sans l'arc) ET les deux bouts ont degré ≥ 3 avant
     retrait (degré ≥ 2 après). Probabilités (héritées P1.2) : paire difficile
     (montagne-montagne, montagne-marécage) 0,75 ; plaine-plaine 0 ; autres 0,15.
   - `capDegrees(arcs, terrain, centroids)` : tant qu'un territoire dépasse
     `maxDegree(terrain)` (`mountain`/`swamp`/`hill` 3 ; `plain`/`forest` 5) : déclasser le
     meilleur candidat — priorité paire difficile, puis plus longue distance centroïdes,
     départage par indices croissants — sous les mêmes gardes (non-pont ∧ degrés ≥ 3). Chaque
     déclassement décroît le nombre d'arcs franchissables → terminaison. Configuration
     irréductible → erreur explicite `mapgen: cannot enforce max degree ...` (pattern existant
     conservé).
   - `validateGraph(passable, terrain, n)` : connexe (BFS), degré ∈ [2, max(terrain)] partout.
   - L'ensemble final = arcs franchissables (`adjacencies`) + arcs déclassés (`impassable`) =
   tous les arcs géométriques ; les deux listes disjointes, triées, symétriques.
6. **Pipeline `Generate`** (`mapgen.go`) : sites → raster → contrôle régions → polygones
   intérieurs (étape 4) → `validateGeometry` → arcs → terrains (sites intérieurs uniquement,
   `assignTerrains` inchangé) → `pruneFrontiers` → `capDegrees` → `validateGraph` → villages
   (`assignVillages`, centroïdes intérieurs) → nommage (`nameTerritories`) → assemblage.
   `Territory` gagne `Impassable []string \`json:"impassable"\``, initialisé à `[]` non `nil`.
   `TerritoriesPerPlayer = 8` exporté et documenté. Doc `Config` : `Width/Height` = viewport de
   génération ; la taille finale est dérivée ; `SiteCount` = nombre de territoires livrés.
7. **Endpoint dev** (`internal/api/map.go` + `cmd/server/main.go`) :
   - `api.MapHandler(resolve func(players int) ([]byte, error))` : parse `?players` (défaut
     4 ; constantes `playersMin=2`, `playersMax=5` documentées dans api) ; non entier ou hors
     bornes → 400 ; erreur `resolve` → 500.
   - `cmd/server` : résolveur avec cache mémoire `map[int][]byte` sous mutex (clé = players ;
     seed fixé au démarrage — spec : clé = seed+players, le seed étant constant en dev, la clé
     players suffit, struct de résolveur portant le seed pour la fidélité) ; wraps
     `mapgen.Generate` avec `Config{Width: 1000, Height: 700, SiteCount: 8×players,
     VillageCount: players+1}` ; log « map generated » au démarrage pour players=4 (fatal si
     erreur, comportement actuel) et à chaque première génération d'une nouvelle clé.
   - `newServer` prend le résolveur en paramètre ; `devVillageCount` supprimé.
8. **Front** (`web/src/types.ts`, `web/src/components/MapViewer.tsx`) :
   - `Territory.impassable: string[]`.
   - Supprimer `AdjacencyArc` (interface, memo `adjacencyArcs`, groupe « Adjacences
     franchissables ») et la légende associée.
   - Frontières partagées : pour chaque paire d'arcs (`adjacencies` ∪ `impassable`), extraire
     les arêtes communes des deux polygones (les sommets sont identiques des deux côtés,
     garantis par le backend ; comparaison exacte sur les entiers) ; rendre chaque arc UNE

   - `mapWidth/mapHeight` : marges symétriques (`mapWidth = maxX + minX`,

     côtés (le padding gauche/haut ≥ padding constant ; droite/bas déduits symétriquement).
   - Légende : « Trait épais continu = frontière infranchissable · Trait fin pointillé =
     frontière franchissable ».
