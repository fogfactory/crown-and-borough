# Prompt P1.5 — Ravitaillement, stocks et famine

```
Tu travailles sur "Crown & Borough", un jeu de stratégie asynchrone par tours.
Le moteur de résolution existe (P1.4, internal/engine : phases 1-5 — intentions,
soutiens, itération, exécution, progression), les modèles sont en place
(internal/models), la génération de carte aussi (internal/engine/mapgen).
Références : specs/gdd.md (§5 Ravitaillement Exponentiel + Portée des Flux,
§7 Infrastructures — Moulin, Dépôt de Vivres, §8 Algorithme de Carence
Alimentaire) et specs/architecture.md.

PÉRIMÈTRE : phase de ravitaillement (production, portée des flux, coût
exponentiel, stocks, famine), branchée dans le moteur existant. L'HIVER
(conservation 50 %, P1.6) et la transmission différée (P2) sont HORS périmètre.

RÈGLE DE CODE : code EXCLUSIVEMENT en anglais (identifiants, commentaires,
messages, enums). Seules les chaînes de contenu de jeu sont en français.

1. INTÉGRATION au moteur (internal/engine) :
   - Insère la PHASE 0 — RAVITAILLEMENT au début de Resolve, AVANT les
     intentions (les phases 1-5 de P1.4 restent, éventuellement renumérotées)
   - La phase 0 travaille sur l'état EN ENTRÉE (positions de début de tour) :
     le coût est calculé sur la taille des piles de début de tour, la famine
     (force = 0) s'applique aux combats du TOUR COURANT
   - La famine est TRANSIENTE : le flag vit dans la résolution (pas persisté
     dans GameState) ; chaque tour recalcule tout
   - Constants moteur : BaseProduction (int, défaut 1), SupplyRange (int,
     défaut 3), DepotRangeBonus (int, défaut 2) — documentées
   - EVENTS ajoutés à Resolution (pour le TurnReport P1.7) : SupplyEvent
     (source, production, demande, stock consommé) et FamineEvent (pile,
     armées faméliques) — pas de formatage ici
   - Itération DÉTERMINISTE : sources par ID de territoire croissant, BFS par
     ID croissant, balayages dans l'ordre des règles ci-dessous

2. PRODUCTION : chaque case LIEU-DIT (Territory.IsLieuDit OU portant un
   Château castle — GDD §7 : le château rend la case lieu-dit, y compris en
   zone sauvage) contrôlée (TerritoryState.OwnerID ≠ nil) produit R_BASE par
   tour, +1 R par niveau de Moulin (mill) placé SUR ce lieu-dit ou sur une
   case DIRECTEMENT ADJACENTE (règle des orphelins GDD §7 simplifiée : un
   moulin hors lieu-dit non adjacent à un lieu-dit ne produit pas). Un
   lieu-dit NEUTRE (non contrôlé) ne produit rien (choix documenté : la
   production n'irrigue que les armées de son contrôleur). Production de
   base non spécifiée par le GDD → R_BASE fixée à 1, documentée.

3. PORTÉE DES FLUX ET AFFECTATION :
   - BFS depuis CHAQUE lieu-dit contrôlé, à travers les cases ALLIÉES ou
     NEUTRES (TerritoryState.OwnerID == celui de la source, ou nil) ; une
     case contrôlée par un ENNEMI BLOQUE le flux
   - Portée de base : SupplyRange (3) ; chaque case avec un Dépôt de Vivres
     DU JOUEUR (supply_depot) rencontrée prolonge la portée restante de +2
     (DepotRangeBonus ; cumulable, une fois par source et par case — GDD §5)
   - Chaque PILE (toutes les armées sur la même case) est affectée à la
     source la PLUS PROCHE qui l'atteint (distance BFS croissante, départage
     : trigramme de la source croissant) ; une pile sans source atteignable
     (hors portée ou bloquée) → Famine directe (étape 6), sans coût, sans
     consommation de stock

4. COÛT ET DÉFICIT :
   - Coût d'une pile de N armées : 2^(N-1) (1 armée = 1 R, 2 = 2 R, 3 = 4 R,
     4 = 8 R) ; le coût est ALL-OR-NOTHING : la pile est l'unité de
     ravitaillement (elle est nourrie ou famélique, jamais partiellement)
   - Demande totale D = somme des coûts des piles affectées ; production
     totale P = somme des productions des sources
   - D ≤ P : tout le monde est nourri ; l'EXCÉDENT de chaque source
     (production_locale - demande_locale si positif) est ajouté à SON stock
     (TerritoryState.Resources)
   - D > P : déficit Δ = D - P → étape 5

5. ÉPUISEMENT DES STOCKS (GDD §8, ordre exact) : balayage des stocks des
   lieux-dits CONTRÔLÉS par le joueur (global à son réseau), du plus PETIT
   au plus GRAND, départage : trigramme du territoire croissant
   (Territory.Code) ; chaque stock est consommé (décrémenté) jusqu'à couvrir
   Δ ; si les stocks totaux suffisent → tout le monde est nourri

6. FAMINE (GDD §8, ordre exact) : le déficit restant (après stocks) famine
   des PILES entières, triées par :
   - distance à leur source DÉCROISSANTE (les plus éloignées meurent de faim
     d'abord)
   - départage : taille de pile DÉCROISSANTE (les plus GROSSES d'abord —
     les plus coûteuses en nourriture)
   - départage final : matricule d'armée DÉCROISSANT (pour une pile : le PLUS
     GRAND matricule de la pile — documenté, la pile étant atomique)
    Chaque pile famélique retire son coût du déficit ; on itère jusqu'à
   couverture. Une pile famélique :
   - a une FORCE = 0 ce tour (attaque ET défense ET soutien, dans les phases
     de combat de P1.4 : elle ne se bat pas) ; si elle est battue, elle bat
     en retraite normalement
   - exécute quand même ses ordres de mouvement (elle se déplace à force 0 ;
     J/D inchangés, puissance 0 de toute façon)
   - PILLAGE AUTOMATIQUE : au moment de la famine (position de DÉBUT de
     tour), chaque pile famélique dont la case porte une infrastructure
     détruit l'infrastructure la PLUS RÉCENTE (même règle de sélection que
     l'ordre P de P1.4) et gagne un gain G = BonusR (constante moteur,
     défaut 2) − Coût de la pile (2^(N-1)) :
       - G ≥ 0 → la pile se NOURRIT d'elle-même : elle n'est PAS famélique
         (force normale ce tour), l'excédent G est crédité au stock du
         LIEU-DIT CONTRÔLÉ LE PLUS PROCHE du joueur (BFS, départage
         trigramme ; perdu s'il n'en contrôle aucun — même convention pour
         le bonus de l'ordre P de P1.4) et son coût est retiré du déficit
       - G < 0 → la pile RESTE famélique (force 0), sans aucun gain
         (l'infrastructure est détruite quand même, elle ne peut pas être
         repillée au tour suivant)
     Le contrôle d'auto-pillage s'applique AUSSI aux piles faméliques SANS
     source atteignable (étape 3) : une pile hors portée sur une
     infrastructure se nourrit par le pillage si G ≥ 0 ; elle ne famélise
     que si G < 0
   - Une pile famélique qui se déplace DANS le tour vers une infrastructure
     ne la pille PAS (le pillage automatique n'a lieu qu'au moment de la
     famine, sur la position de début de tour)

7. ÉTAT RETOURNÉ : TerritoryState.Resources mis à jour (stocks consommés,
   excédents ajoutés) ; aucune autre mutation ; Resolution.Events contient
   les SupplyEvent/FamineEvent

8. TESTS (internal/engine/supply_test.go, scénarios exhaustifs) :
   - Coût exponentiel : 1 → 1 R, 2 → 2 R, 3 → 4 R, 4 → 8 R
   - Équilibre : pile de 1 sur son lieu-dit contrôlé (prod 1) → nourrie,
     stock inchangé ; excédent (prod 2 = lieu-dit + moulin lvl 1, demande 1)
     → +1 au stock
   - Déficit couvert par stocks : prod 1, pile de 3 (4 R), stock 3 → stock à
     0, tout le monde nourri ; tour suivant : déficit 4, stock 0 → famine
   - Ordre d'épuisement : stocks 2 et 5, Δ = 3 → le stock 2 est épuisé
     d'abord puis 1 prélevé sur le stock 5 ; stocks égaux → trigramme
     croissant d'abord
   - Ordre de famine : trois piles nourries par la même source (distances 1,
     1 et 3), capacité insuffisante → la pile à distance 3 famine d'abord ;
     puis départage GROSSEUR : mêmes distances → la pile la plus grosse
     (3 armées) famine avant la plus petite (1 armée) ; même distance ET même
     taille → matricule DÉCROISSANT d'abord
    - AUTO-PILLAGE : pile de 1 famélique sur une case avec infra → gain
      2−1 = 1 ≥ 0 : nourrie (force normale), +1 au stock du lieu-dit
      contrôlé le plus proche, infra détruite, coût retiré du déficit (une
      autre pile est épargnée) ; pile de 3 → gain 2−4 = −2 < 0 : reste
      famélique, infra détruite, aucun gain ; pile de 2 → gain 0 : nourrie
      exactement, rien crédité ; pile hors portée mais sur une infra →
      nourrie si gain ≥ 0, famélique sinon ; pile famélique se déplaçant
      sur une infra → aucun pillage ; pile SANS lieu-dit contrôlé →
      excédent perdu (mais nourrie si gain ≥ 0)
   - Déterminisme + cohérence (stock ≥ 0, événements alignés sur l'état)
   - Hors portée : armée à distance 4 (portée 3) → famine ; armée derrière
     une case contrôlée par l'ennemi → famine (blocage du flux)
   - Dépôt de Vivres : armée à distance 5, source portée 3 → famine ; avec un
     Dépôt sur le chemin (à distance 3) → nourrie ; distance 6 avec Dépôt →
     famine
   - Force 0 : pile famélique attaquée par 1 → l'attaquant gagne ; pile
     famélique attaquant une case défendue (déf 1) → échec, défense tient ;
     pile famélique vers case vide → succès (elle se déplace) ; soutien S
     d'une pile famélique = 0
   - Multi-joueurs : la source du joueur A ne nourrit PAS les armées du
     joueur B (même si B est à portée) ; source neutre → production 0
   - Moulin orphelin : moulin sur case non adjacente à un lieu-dit → sa
     production ne compte pas ; moulin sur lieu-dit ou adjacent → compte
   - DÉTERMINISME : deux appels Resolve sur le même état → résultats
     identiques (état final + événements) ; cohérence de l'état retourné
     (stocks ≥ 0, famines cohérentes avec les événements)
```
