# Prompt P0.2 — Assets CSV + loader Go

```
Tu travailles sur "Crown & Borough", un jeu de stratégie asynchrone. Le squelette
Go existe déjà (cmd/server, internal/, assets/ vide, Makefile). Références :
specs/architecture.md (section Assets) et specs/gdd.md (départage alphabétique
des trigrammes).

Tâche : générer les données statiques du monde + le loader Go.

RÈGLE DE CODE : le code est EXCLUSIVEMENT en anglais (identifiants, noms de
fichiers, commentaires, messages d'erreur/log, valeurs d'enums). Seules les
chaînes de contenu de jeu (noms de communes, prénoms, labels UI) sont en
français, langue du jeu.

1. Génère 2 fichiers CSV dans assets/ (séparateur ";" , en-tête en 1re ligne) :

   a) communes.csv : 400-500 noms de communes (style médiéval français :
       Villeneuve, Rosemont, Mont-Dore...) avec leur code trigramme et leur
       affinité de terrain.
       Format : code;nom;terrain
       terrain : plain | forest | hill | mountain | swamp | any ; chaque
       affinité doit être représentée.

   b) prenoms.csv : ~120 prénoms MÉDIÉVAUX FRANÇAIS authentiques (Guillaume,
      Hugues, Amaury, Mathilde, Adélaïde...) avec leur code trigramme.
      Format : code;nom

   Règles sur les codes des communes et prénoms :
   - TRIGRAMMES STRICTS : exactement 3 lettres MAJUSCULES A-Z (accentués
     translittérés : É→E), mnémotechniques quand possibles (VIL pour Villeneuve)
   - Codes uniques au sein de CHAQUE fichier uniquement (un prénom peut avoir
     le même trigramme qu'une commune : le type d'entité lève l'ambiguïté)
   - Noms uniques dans chaque fichier, aucun nom vide

2. Crée un package Go de chargement (suit la convention du repo, ex.
   internal/db/assetgen) qui :
    - charge les 2 CSV au démarrage (dir passé en paramètre)
    - vérifie les invariants : unicité des codes au sein de chaque fichier
      (communes, prénoms — pas d'unicité inter-fichiers), unicité des noms par
      fichier, terrain de commune valide, couverture des affinités et ligne
      malformée
      → erreur explicite (crash au démarrage si invalide)
    - expose :
        type Asset struct { Code string; Name string }
        type Commune struct { Code string; Name string; Terrain string }
        type Assets struct {
            Communes []Commune
            Prenoms []Asset
        }
        func Load(dir string) (Assets, error)

3. Tests unitaires : chargement depuis assets/ réel (invariants OK), détection
   d'un doublon et d'un CSV malformé (fichiers temporaires en test).

4. Intègre le chargement au démarrage de cmd/server (log des compteurs ;
   échec = crash explicite).

Critères d'acceptation :
- make test passe (loader + invariants vérifiés)
- make run logue les compteurs d'assets au démarrage
- Tous les trigrammes font exactement 3 lettres ; tous les terrains de
  communes font partie de la liste autorisée
  (plain|forest|hill|mountain|swamp|any) ; pas de doublon de code ni de nom
  au sein d'un même fichier ; chaque affinité est présente

Note : les noms et codes de TERRITOIRES viennent des communes à la génération
de carte (P1.2).

Ne commite pas : je m'en charge.
```
