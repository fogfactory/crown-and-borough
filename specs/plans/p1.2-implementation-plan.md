# Plan P1.2 — Génération de carte Voronoï (à déléguer)

Brief d'exécution autonome pour un modèle d'implémentation.

## Contexte

Squelette P0.1 + assets P0.2 + modèles P1.1 en place : `cmd/server` (charge les assets via
`assetgen.Load`, sert `/healthz` via `newServer()`), `internal/models` (Territory/GameState/enums —
**ne pas modifier**), `internal/db/assetgen` (style de référence : commentaires anglais, erreurs
préfixées), `internal/{api,engine}` vides (`.gitkeep`), Go 1.26, zéro dépendance tierce, Makefile
(`test` = `go test ./...`, `vet` = `go vet ./...`, `run`, `web-dev`). Front React : `MapViewer`
générique (props `map`/`state`) alimenté par `src/fixtures/map.ts` (12 territoires, viewBox 640×480
en dur) et `src/fixtures/state.ts`. Le prompt source est `specs/prompts/p1.2-generation-carte.md` —
le lire en entier avant de commencer. Références : `specs/gdd.md` §3 (frontières infranchissables,
routes, lieux-dits), `specs/roadmap.md` (P1.2 détaillé), `specs/architecture.md` §4-5 (convention de
code, contrat map.json).

Règles absolues :

- Code exclusivement en anglais ; seules les chaînes de contenu de jeu (noms de communes,
  qualificatifs) sont en français.
- Stdlib uniquement (pas de lib Voronoï : la méthode grille du prompt suffit).
- Déterminisme strict : `Generate` est une fonction pure de `(seed, assets, cfg)` — aucune horloge,
  aucun aléa non seedé, **aucune itération de map Go** dans un ordre non trié (utiliser des slices
  ou des clés triées).
- Ne rien commiter. Ne pas modifier `internal/models` ni les specs.

## Difficulté et modèle recommandé

Difficulté **4/5** — la plus dure du palier P1 : extraction de polygones depuis une grille, invariant
de graphe (connexité + degré ≥ 2) avec réparation par routes, collisions de nommage, discipline de
déterminisme byte-for-byte. ~1 300 lignes au total (dont ~400 de tests). Modèle à fort raisonnement
conseillé (Claude Sonnet/Opus, GPT-5-class, ou K2-thinking) — un modèle budget risque de boucler sur
les cas limites géométriques (chaînage de frontières aux jonctions triples).

## Décisions de conception (à appliquer et documenter dans le code)

1. **RNG par phase** : `newRNG(seed, phase string) *rand.Rand` — `sha256(seed + "|" + phase)` →
   deux uint64 → `rand.New(rand.NewPCG(lo, hi))` (`math/rand/v2`). Phases : `"sites"`, `"terrain"`,
   `"lieudit"`, `"frontiers"`, `"naming"`. Chaque phase est indépendante et insensible à l'ordre
   d'appel — déterminisme robuste.
2. **Méthode grille (stdlib)** : raster 256×160 (constantes `gridW`, `gridH`) sur le viewport
   `cfg.Width×cfg.Height`. Assignation au site le plus proche en distance euclidienne **au carré**,
   départage par plus petit index de site (déterministe, pas de `math.Sqrt` inutile).
3. **Sites en grille jitterée** : `cols×rows` couvrant `SiteCount`, site = centre de cellule +
   jitter uniforme seedé ∈ ±0,35 cellule, clampé au viewport ; cellules surnuméraires retirées par
   tirage seedé. Garantit couverture (bords compris) **et** tailles inégales.
4. **Polygones par chaînage de frontières** : pour chaque site, segments d'arêtes de grille entre
   cellule du site et voisin différent/hors-grille (sommets = coordonnées entières de grille
   0..256 × 0..160) ; chaînage en boucle fermée par règle de la main droite avec priorité de
   direction fixe (cas des jonctions triples) ; on garde la **plus grande boucle** (défensif :
   région disconnectée quasi impossible en Voronoï). Mise à l'échelle viewport, arrondi à l'entier,
   dédup des points consécutifs, suppression des points colinéaires. `Points [][2]int`.
5. **Adjacence géométrique** : deux sites adjacents ssi ≥ `minSharedEdges = 3` arêtes de grille
   partagées (seuil documenté, élimine les contacts ponctuels). Symétrique par construction ; paires
   itérées triées.
6. **Terrains par zones contiguës** : `K = max(5, SiteCount/8)` « graines de terrain » (sites tirés
   par shuffle seedé) ; les 5 premières reçoivent une permutation seedée des 5 terrains (**présence
   garantie de chaque terrain**), les autres un tirage pondéré (plain 35 %, forest 25 %, hill 20 %,
   mountain 10 %, swamp 10 %). Chaque site hérite du terrain de la graine la plus proche → zones
   contiguës.
7. **Frontières infranchissables** : pour chaque paire géométrique (ordre trié), probabilité de
   suppression : mountain↔mountain et mountain↔swamp = **0,75**, plain↔plain = **0**, tout le reste
   = **0,15** (tirage phase `"frontiers"`).
8. **Réparation (invariant absolu)** : (a) tant que le graphe est déconnecté : route entre la paire
   (a ∈ C1, b ∈ C2) minimisant `(distance centroïdes, idA, idB)` ; (b) tant qu'un territoire a
   degré < 2 (par id croissant) : route vers le non-adjacent minimisant `(distance, id)`. Choix
   déterministes dérivés de la géométrie seedée (le « choix seedé » du prompt), terminaison garantie
   (chaque route augmente deux degrés). Les routes sont fusionnées dans `adjacencies` — **contrat
   map.json strict, pas de champ `roads`** (point ouvert pour P2.2 : l'identité des routes est
   régénérable depuis le seed).
9. **Nommage** :
   - Lieux-dits : `round(SiteCount × LieuDitRatio)` sites choisis par shuffle seedé (`"lieudit"`),
     terrain inchangé ; communes assignées dans l'ordre d'un shuffle seedé de `assets.Communes`
     (≤ 1 lieu-dit par commune) ; nom = nom de commune, code = trigramme.
   - Non-lieux-dits : candidats communes = lieux-dits **adjacents du graphe final** triés par
     `(distance centroïde, id)`, puis tous les autres lieux-dits au même ordre (fallback « plus
     proche »). Candidats qualificatifs = `assets.Qualificatifs` **dans l'ordre du CSV**, filtrés
     `terrain == t` ; `terrain == "any"` (Marches) éligible **uniquement si le territoire touche le
     bord du viewport** (au moins un point à x=0, x=Width, y=0 ou y=Height). Ordre d'essai : pour la
     commune préférée, qualificatifs dans l'ordre CSV ; si tous épuisés, commune suivante et on
     recommence. Contraintes : paire (qualificatif, commune) unique **et** code unique (impliqué par
     la paire, préfixes et trigrammes uniques) ; code = `prefix + trigramme` (4 lettres A-Z). Erreur
     si épuisement total (défensif).
10. **Types JSON** : `mapgen.Territory` propre au package (la géométrie vit ici) avec
    `Terrain models.Terrain` (import en lecture seule de `models` — aucune modification) ; `ID` =
    `T%02d` dans l'ordre des sites ; `Adjacencies` triées ; `MapData{Territories []Territory}`
    **sans aucune map Go** → `json.Marshal` byte-for-byte stable.
11. **Validation de `Config`** : `Width, Height ≥ 100`, `SiteCount ≥ 8`, `LieuDitRatio ∈ (0, 0.5]` ;
    erreurs explicites aussi si assets insuffisants (aucune commune, aucun qualificatif pour un
    terrain rencontré).
12. **Endpoint** : carte générée **une fois au démarrage** (seed = `os.Getenv("SEED")` ou constante
    par défaut `"crown-and-borough-dev"`, loguée), JSON pré-marshallé en `[]byte`, handler qui ne
    fait qu'écrire les octets.

## Étape 1 — `internal/engine/mapgen/` : types et orchestration (~130 lignes)

`mapgen.go` :

```go
// Package mapgen generates the static world map (map.json contract) ...
type Config struct {
    Width, Height int     // viewport, e.g. 1000x700
    SiteCount     int     // e.g. 64
    LieuDitRatio  float64 // e.g. 0.25
}

type Territory struct {
    ID          string         `json:"id"`
    Code        string         `json:"code"`
    Name        string         `json:"name"`
    Terrain     models.Terrain `json:"terrain"`
    LieuDit     bool           `json:"lieuDit"`
    Points      [][2]int       `json:"points"`
    Adjacencies []string       `json:"adjacencies"`
}

type MapData struct {
    Territories []Territory `json:"territories"`
}

func Generate(seed string, assets assetgen.Assets, cfg Config) (MapData, error)
```

`Generate` valide la config puis orchestre : `generateSites` → `assignRaster` → `extractPolygons`
+ `extractAdjacency` → `assignTerrains` → `filterFrontiers` → `repairGraph` (routes) →
`assignLieuDits` + `nameTerritories` → assemblage trié. `rng.go` : `newRNG(seed, phase)`.

## Étape 2 — Sites et raster (~260 lignes)

- `sites.go` : `generateSites(rng, cfg) []point` (float64) — grille jitterée (décision 3).
- `raster.go` :
  - `assignRaster(sites, cfg) []int` — grille 256×160, owner de chaque cellule (décision 2) ;
    vérifie qu'aucune région n'est vide.
  - `extractPolygons(grid, sites, cfg) ([][][2]int, [][2]float64)` — polygones chaînés main droite
    + simplification (décision 4) et centroïdes (moyenne des sommets, utilisée pour distances et
    routes).
  - `extractAdjacency(grid) [][2]int` — paires triées avec ≥ 3 arêtes partagées (décision 5).

## Étape 3 — Graphe : terrains, frontières, routes (~230 lignes)

- `terrain.go` : `assignTerrains(rng, sites) []models.Terrain` (décision 6).
- `graph.go` :
  - `filterFrontiers(rng, edges, terrains) [][2]int` (décision 7).
  - `repairGraph(edges, centroids, n) [][2]int` — connexité (BFS composantes) puis degrés ≥ 2,
    routes ajoutées (décision 8) ; helpers `components`, `degrees`.
  - Invariant final revérifié en fin de `Generate` (connexe + degré min ≥ 2, sinon erreur interne —
    filet de sécurité).

## Étape 4 — Nommage (~150 lignes)

## Étape 7 — Tests `internal/engine/mapgen/mapgen_test.go` (~400 lignes)

Assets : réels via `assetgen.Load("../../../assets")` (convention du repo) + helper d'assets
synthétiques minimaux (style `writeAssets` d'assetgen) pour les cas limites de nommage (peu de
communes/qualificatifs → collisions forcées). Config de test : `{1000, 700, 64, 0.25}`. Seeds : au
moins 5 (ex. `"alpha"`, `"beta"`, `"gamma"`, `"delta"`, `"epsilon"`).

- `TestDeterminism` : deux `Generate` même seed → `reflect.DeepEqual` **et** octets `json.Marshal`
  identiques ; deux seeds différents → JSON différents.
- `TestGraphInvariants` (tous seeds) : adjacences symétriques, pas d'auto-adjacence ni doublon,
  cibles existantes ; BFS depuis chaque territoire atteint tout ; **degré ≥ 2 pour TOUT territoire**.
- `TestLieuDitRatio` : ratio ∈ [0,20 ; 0,30] sur chaque seed.
- `TestCodes` : `^[A-Z]{3}$` si lieu-dit, `^[A-Z]{4}$` sinon ; unicité globale par carte, sur tous
  seeds.
- `TestNaming` : noms non vides ; non-lieu-dit matche `^<Qualif> de <Commune>$` avec qualif présent
  dans les assets et compatible terrain (ou Marches si bordure) ; chaque terrain présent au moins
  une fois.
- `TestNamingCollisions` (assets synthétiques) : 2 qualificatifs même terrain + 2 communes → 4
  noms/codes distincts déterministes.
- `TestGeometry` : polygones ≥ 3 points, aire (shoelace) > 0, tous points dans
  `[0,Width]×[0,Height]` ; white-box (même package) : grille raster intégralement assignée, aucune
  région vide.
- `TestConfigValidation` : configs invalides → erreur.
