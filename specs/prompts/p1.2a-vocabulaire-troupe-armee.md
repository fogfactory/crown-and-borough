# Prompt P1.2a — Vocabulaire : troupe (unité) et armée (pile)

```
Tu travailles sur "Crown & Borough", un jeu de stratégie asynchrone par tours.
Les modèles métier existent (P1.1, internal/models), la génération de carte
aussi (P1.2, internal/engine/mapgen + endpoint /api/map), le front React
(web/) affiche la carte (MapViewer) avec une fixture d'état (web/src/fixtures).
Références : specs/gdd.md, specs/architecture.md, specs/roadmap.md et les
prompts specs/prompts/p1.1-modeles-metier.md, p1.3-ordres-chaines.md,

p1.6-hiver-investissements.md, p1.7-rapport-tour-hotseat.md, p2.x, p3.x.

Tâche : refactor TERMINOLOGIQUE complet. Deux mots changent de sens dans le
jeu (langue du jeu = français) :

- "troupe" = l'unité individuelle de force (actuellement nommée "armée").
  1 troupe = 1 force ; un matricule par troupe ; recrutement d'une troupe.
- "armée" = le GROUPE de troupes occupant la même case (actuellement nommé
  "pile"). Les ordres, le ravitaillement (unité atomique nourrie ou
  famélique) et la famine s'appliquent aux armées, jamais individuellement
  aux troupes.

En anglais (le code), la correspondance est naturelle : "troop" = l'unité,
"army" = le groupe. Le modèle actuel models.Army (l'unité) devient donc
models.Troop ; le concept de "pile" n'a pas de type dédié dans les modèles —
là où le code ou les specs parlent de "stack"/"pile" (ravitaillement,
famine), on écrit désormais "army"/"armée".

RÈGLE DE CODE : code EXCLUSIVEMENT en anglais (identifiants, commentaires,
messages, JSON tags). Seules les chaînes de contenu de jeu (noms de
communes, prénoms, noms de territoires) sont en français.

1. CODE (Go, internal/models + tests + front) :

     "territory" inchangés).

     "troops"), TerritoryState.Armies → Troops (JSON "armies" → "troops"),
     variables/helpers associés (ex. seenArmies → seenTroops).

     territoires "T01", nobles "N1", troupes "TR1" (l'ancien "A1" est
     abandonné car "armée" désigne maintenant le groupe ; "T" est réservé

     round-trip, conventions "TR1").

     "troops"), les usages dans App.tsx / MapViewer.tsx / fixtures.

     ni Army ni Troop ; vérifie seulement qu'aucune fuite de vocabulaire n'y
     traîne.
- Grep final : plus aucun IDENTIFIANT ni chaîne "Army"/"armies"/"pile"
     dans le code Go et TS (internal/, web/src) ; les commentaires peuvent
     employer "army"/"armée" au sens NOUVEAU (le groupe de troupes) si le
     contexte l'exige — sinon reformule. Les docs réécrites ne contiennent

2. RÉÉCRITURE DES DOCS ET PROMPTS (cette tâche DÉROGE explicitement à la

   toucher aux règles de jeu, aux mécaniques ni au format des ordres).

   Table de substitution (systématique) :
   | Avant | Après |
   |---|---|---|
   | armée (unité individuelle) | troupe |
   | pile (groupe sur une case) | armée |
   | Army / armies (code, JSON) | Troop / troops |
   | pile famélique | armée famélique |
   | taille de la pile | taille de l'armée |
   | les piles les plus grosses | les armées les plus grosses |
   | matricule d'armée | matricule de troupe |
   | recruter une Armée, ordre `R A` | recruter une Troupe, ordre `R T` |
   | Numéro d'armée (GDD famine) | Numéro de troupe |
   | première armée du joueur présente (réception de chaîne) | première troupe du joueur présente |
   | rapports des armées / chaque armée produit un rapport | rapports des troupes / chaque troupe produit un rapport |
   | pile sans ordre / IA "sans ordre" (P2.1) | armée sans ordre (le "Sans Ordre" est une propriété du GROUPE — la pile ; il ne faut PAS écrire "troupe sans ordre") |
   | armées = force de base 1 armée = 1 force | troupes : 1 troupe = 1 force |

   - l'ordre de mouvement/attaque `XXX A YYY` (A = Attaque), ni S/H/J/P/D/O/K ;
   - les ordres d'hiver autres que le recrutement : `R N` (noble), `C M`,

   - les noms de concepts hors périmètre (lieux-dits : traités par un autre
     prompt ; territoires, nobles, infrastructures : inchangés).

     p1.4-resolution-combat.md, p1.5-ravitaillement-famine.md,
```
