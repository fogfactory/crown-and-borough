# Prompt P1.4 — Moteur de résolution : intentions, combats, retraites, progression

```
Tu travailles sur "Crown & Borough", un jeu de stratégie asynchrone par tours.
Le parser et les modèles d'ordres/chaînes existent (P1.3, internal/models +
package de parsing), la génération de carte est en place (internal/engine/mapgen).
Références : specs/gdd.md (§5 Combats, §6 Retraites, §8 Contrôle territorial)
et specs/architecture.md (§6 — sémantique des ordres, à suivre à la lettre).

PRINCIPE FONDAMENTAL : on ne sépare PAS les déplacements des combats. La
résolution est de type Diplomacy : on énumère d'abord TOUTES les intentions
(qui veut aller où, avec quelle puissance), on calcule les soutiens, on
ITÈRE jusqu'à stabilité, et seulement ensuite on exécute les mouvements.

PÉRIMÈTRE : résolution simultanée des ordres de TOUTES les chaînes, combats,
retraites, contrôle territorial, progression des chaînes. RAVITAILLEMENT/
famine (P1.5), HIVER (P1.6) et transmission différée (P2) HORS périmètre
(vision T0) : le moteur est conçu en phases pour s'y brancher.

RÈGLE DE CODE : code EXCLUSIVEMENT en anglais (identifiants, commentaires,
messages, enums). Seules les chaînes de contenu de jeu sont en français.

1. Interface (internal/engine) :
   - Resolve(game *models.GameState) (Resolution, error) — fonction PURE,
     déterministe, sans I/O
   - Resolution : EVENTS structurés (outcomes par ordre, combats, retraites,
     fusions, pillages, dispersions, changements de contrôle) que P1.7
     formatera en TurnReport — pas de formatage ici
   - Architecture en PHASES :
       Phase 1 — Énumération des intentions (mouvements et puissances)
       Phase 2 — Calcul des soutiens
       Phase 3 — Itération de résolution jusqu'à stabilité (combats)
       Phase 4 — Exécution des mouvements + retraites
       Phase 5 — Progression des chaînes + contrôle territorial
     Points d'extension clairs pour ravitaillement (P1.5) et propagation
     (P2). Itération DÉTERMINISTE : armées par matricule croissant,
     territoires par ID.

2. Phase 1 — Intentions : pour chaque territoire, lister les armées qui
   veulent s'y rendre selon leur ordre courant :
   - A (attaque/atteindre) : intention de déplacement CONTESTÉE ; chaque
     pile attaquante est un contendant distinct — puissance = nombre
     d'armées de CETTE pile ciblant la même case (une pile de N qui se
     déplace ensemble = force N) ; les attaques de piles d'origines
     DIFFÉRENTES ne se combinent PAS (il faut un soutien S pour cumuler)
   - J (jonction) / D (dispersion) : déplacements PACIFIQUES, puissance 0
     (ils ne contestent pas la case)
   - H / P / S : pas de mouvement (reste, pillage, soutien)
   - Position exigée : armée absente de la position de l'ordre → failure
     (pas d'intention émise)

3. Phase 2 — Soutiens : chaque ordre S de la pile P soutient la case YYY
   avec la PUISSANCE = TAILLE DE LA PILE P (pas 1 par armée) :
   - Direction : AU CONTENDANT ALLIÉ de YYY — si un allié ATTAQUE YYY, le
     soutien s'ajoute à sa force d'attaque ; sinon si un allié OCCUPE YYY,
     le soutien s'ajoute à sa défense ; sans contendant allié → l'ordre
     échoue (failure)
   - COUPURE : une pile qui soutient voit son soutien ANNULÉ si elle est
     elle-même attaquée ce tour (règle Diplomacy)
   - Si aucune attaque ne cible YYY : le soutien est gaspillé mais l'ordre
     réussit (et en loop : la chaîne avance — cf. Phase 5)

4. Phase 3 — Itération jusqu'à stabilité (manière Diplomacy) :
   Répéter jusqu'à ce que plus rien ne change (fixé) :
   a. Forces d'attaque : pour chaque PILE attaquante, force = nombre
      d'armées de la pile ciblant la case + soutiens non coupés des piles
      alliées (Phases 2-3). Les attaques de piles d'origines DIFFÉRENTES
      sont des contenants DISTINCTS, même alliés : elles ne s'additionnent
      jamais
   b. Forces de défense : force = taille de la pile occupant la case +
      château +1 (si présent) + soutiens non coupés des alliés occupants
   c. Coupure des soutiens : les soutiens des piles attaquées ce tour sont
      annulés (leur pile est la cible d'une attaque ennemie)
   d. Résolution des cases contestées : comparaison unique de toutes les
      forces (chaque pile attaquante + la défense) ; la force STRICTEMENT
      la plus haute l'emporte ; TOUTE égalité au sommet → statu quo
      (défense tient, tous les attaquants échouent, leurs A sont des
      failures) — y compris entre attaques alliées (ex. deux attaques de
      1 contre une défense de 1 : statu quo ; pour prendre, une attaque
      SOUTENUE par une pile S : 1 + 1 > 1)
   e. Les J/D vers une case contestée par une attaque ce tour sont
      REPOUSSÉS (bounce, failure), quel que soit le résultat de l'attaque
   - A vers une case occupée par un ALLIÉ : failure (pas d'attaque d'allié)
   - A vers une case VIDE : succès direct (pas de combat)

5. Phase 4 — Exécution des mouvements et retraites :
   - Les attaquants gagnants occupent la case conquise ; les attaquants
     perdants restent sur place ; les J/D repoussés restent sur place
   - Fusion : toute armée alliée arrivant sur une case occupée par un allié
     (déjà présent ou arrivé ce tour) FUSIONNE (la pile devient N armées)
   - P (pillage) : cible = la case de l'armée ; détruit UNE infrastructure
     (la plus récente) + bonus R (constante moteur, défaut : 2) ; aucune
     infrastructure → invalid
   - D (dispersion) : les destinations libres et non contestées sont
     rejointes ; l'armée d'origine (porteuse de la chaîne) prend la
     PREMIÈRE destination listée ; les autres armées sont CRÉÉES (matricule
     suivant — compteur dans GameState si nécessaire, documente) ; toute
     destination non résolue → ordre non résolu intégralement
   - NOBLES — chevauchée (GDD §6) : après les mouvements, les nobles de
     chaque case suivent les armées :
       * pile qui se déplace en bloc (A/J/retraite vers une même
         destination) → le noble la suit
       * D : répartition par ASTÉRISQUE (parser P1.3) — `*` seul = tous les
         nobles restants, `*CODE` = noble désigné (chaque noble au plus une
         fois) ; nobles non désignés ou sans astérisque → armée d'origine
         (1re destination)
       * pile éclatée par des A vers des destinations différentes (sans D) :
         le noble suit l'armée au PLUS PETIT MATRICULE (déterministe,
         documenté)
       * PRISONNIER : un noble prisonnier suit les mêmes règles de chevauchée
         (il se déplace avec l'armée qui le détient, selon les ordres du
         joueur de cette armée)
   - NOBLES — capture (GDD §6) : si la pile que chevauche un noble est
     DÉTRUITE (pas de retraite possible ou collision de repli) ET qu'une
     armée ENNEMIE occupe sa case → le noble devient PRISONNIER de ce joueur
     (LocationID = la case, statut prisoner) ; récupéré par l'armée
     gagnante ; pile détruite sur case vide/alliée → le noble reste sur
     place (non capturé, cas limite toléré) ; le noble n'est jamais détruit
     ni compté dans les forces ni dans le ravitaillement
   - RETRAITES (GDD §6) : une pile battue se replie EN BLOC vers une case
     adjacente valide (non occupée, non ciblée par un combat ce tour,
     différente de la case d'origine de l'attaquant — choix documenté) ;
     deux piles vers la même case de repli → les deux DÉTRUITES ; aucune
     case valide → DÉTRUITE ; plusieurs valides → choix déterministe
     (première par ordre d'ID — un choix joueur viendra plus tard)

6. Phase 5 — Progression des chaînes et contrôle territorial :
   - Par ordre exécuté, outcome ∈ { success, failure, invalid } :
     - success → CurrentIndex++ (chaîne consommée si dernier ordre, armée
       Sans Ordre)
     - failure → single : chaîne BRISÉE (armée Sans Ordre) ; loop : index
       inchangé (retentative au tour suivant)
     - invalid → chaîne BRISÉE dans les deux modes
   - Boucle de veille (H/J en loop) : index figé, jamais d'échec
   - S en LOOP : si AUCUNE attaque ne cible YYY ce tour → SUCCÈS (avance) ;
     si une attaque cible YYY → soutien donné, index INCHANGÉ
   - Boucle "coincée" (position devenue inaccessible) : retente
     indéfiniment — comportement attendu, le joueur remplace la chaîne
   - CONTRÔLE TERRITORIAL (GDD §8) : toute case occupée en fin de résolution
     (arrivée, fusion, conquête) bascule sous le contrôle du propriétaire
     des armées qui l'occupent (TerritoryState.OwnerID) ; rémanence : le
     contrôle persiste après le départ des armées, jusqu'au passage d'un
     ennemi

7. Tests (internal/engine/resolve_test.go, scénarios exhaustifs) :
   - Mouvement : case vide (succès + contrôle), case alliée (failure A),
     position manquante (failure), J/D repoussés sur case contestée
   - Combat : égalité = statu quo ; supériorité = victoire + retraite ;
     défenseur sans case valide = détruit ; collision de repli = les deux
     détruits ; soutien S décisif (attaque ET défense, puissance = pile) ;
     soutien COUPÉ (pile soutenante attaquée) ; château +1 ; pile de N
     attaquant ensemble = force N (contendant unique) ; deux attaques
     ALLIÉES de piles distinctes sur la même case = contenants séparés
     (1+1 vs 1 → statu quo) ; attaque SOUTENUE (1+1) vs 1 → victoire ;
     multi-attaquants ennemis (conflit, égalité) ; itération stable (deux
     passes identiques)
   - J : fusion avec allié présent / arrivé le même tour ; ennemi = failure
   - D : intégrale vs partielle (single avance, loop retente) ; destination
     attaquée ; chaîne suit l'armée d'origine sur la 1re destination ;
     création d'armées avec matricules
   - P : infrastructure détruite + bonus R ; sans infrastructure = invalid
     (brise dans les deux modes)
   - S loop : sortie quand plus d'attaque ; index figé pendant l'attaque ;
     sans contendant allié = failure
   - Progression : single/loop/invalid appliqués sur chaînes MIXTES ;
     veille H/J ; chaîne consommée ; boucle coincée
   - Contrôle : conquête, rémanence après départ
   - Nobles : chevauchée avec une pile en bloc (A/J/retraite) ; répartition
     D par astérisque (`XXX*`, `YYY*JEST`, `YYY*JEST*ANOT`, sans
     astérisque → armée d'origine) ; pile éclatée en A → plus petit
     matricule ; prisonnier qui suit son ravisseur ; CAPTURE : pile détruite
     (pas de retraite/collision) + ennemi sur la case → prisonnier du
     gagnant ; pile détruite sur case vide/alliée → pas de capture ; noble
     jamais détruit, jamais compté dans les forces
   - DÉTERMINISME : deux appels Resolve sur le même état → résultats
     identiques (état final + événements)
   - Cohérence de l'état retourné (armées sur des territoires existants,
     piles cohérentes avec les fusions, compteur de matricules juste)

Critères d'acceptation :
- make test passe ; make vet passe ; aucune dépendance tierce ajoutée
- Resolve est pure, déterministe, sans I/O
- Les événements produits suffisent à construire un TurnReport (P1.7) sans
  accès à l'état interne
- Les phases sont identifiables pour insérer ravitaillement (P1.5) et
  propagation (P2) sans refactor majeur

Note : documente dans ta réponse finale les choix ouverts que tu as tranchés
(puissance de soutien d'une pile partiellement en S, ordre des destinations
dans un repli, compteur de matricules...) pour mise à jour des specs (ne
modifie pas les specs toi-même). Ne commite pas : je m'en charge.
```
