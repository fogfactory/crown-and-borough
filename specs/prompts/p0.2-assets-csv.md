# Prompt P0.2 — Assets CSV + loader Go

```
Tu travailles sur "Crown & Borough", un jeu de stratégie asynchrone. Le squelette
Go existe déjà (cmd/server, internal/, assets/ vide, Makefile). Références :
specs/architecture.md (section Assets) et specs/gdd.md (départage alphabétique
des trigrammes).

Tâche : générer les données statiques du monde + le loader Go.

RÈGLE DE CODE : le code est EXCLUSIVEMENT en anglais (identifiants, noms de
fichiers, commentaires, messages d'erreur/log, valeurs d'enums). Seules les
chaînes de contenu de jeu (noms de communes, prénoms, qualificatifs) sont en
français, langue du jeu.

1. Génère 2 fichiers CSV dans assets/ (séparateur ";" , en-tête en 1re ligne) :

   a) communes.csv : ~200 noms de communes (style lieux-dits : Villeneuve,
      Rosemont, Griffecourt...) avec leur code trigramme.
      Format : code;nom

   b) prenoms.csv : ~120 prénoms MÉDIÉVAUX FRANÇAIS authentiques (Guillaume,
      Hugues, Amaury, Mathilde, Adélaïde...) avec leur code trigramme.
      Format : code;nom

   Règles sur les codes des communes et prénoms :
   - TRIGRAMMES STRICTS : exactement 3 lettres MAJUSCULES A-Z (accentués
     translittérés : É→E), mnémotechniques quand possibles (VIL pour Villeneuve)
   - Codes uniques au sein de CHAQUE fichier uniquement (un prénom peut avoir
     le même trigramme qu'une commune : le type d'entité lève l'ambiguïté)
   - Noms uniques dans chaque fichier, aucun nom vide

2. Génère assets/qualificatifs.csv : une petite liste (~8-10) de qualificatifs
   de territoire utilisés pour nommer les territoires à la génération de carte
   (tâche ultérieure P1.2).
   Format : prefix;qualificatif;terrain
   - prefix : UNE lettre MAJUSCULE, unique entre qualificatifs
   - qualificatif : nom au singulier/pluriel selon usage ("Forêt", "Monts",
     "Collines", "Plaines", "Marais", "Marches"...)
   - terrain : type auquel le qualificatif s'applique, en ANGLAIS (valeurs
     d'enum = code) parmi
     plain | forest | hill | mountain | swamp | any
     ("Marches" peut être "any" : les marches existent sur tout relief)
   Exemple de ligne : F;Forêt;forest
   Le nom d'un territoire sera "Qualificatif de <Commune>" (ex. "Forêt de
   Rosemont") et son code "prefix + trigramme de la commune" (ex. FROS).

3. Crée un package Go de chargement (suit la convention du repo, ex.
   internal/db/assetgen) qui :
   - charge les 3 CSV au démarrage (dir passé en paramètre)
   - vérifie les invariants : unicité des codes au sein de chaque fichier
     (communes, prénoms, prefixes — pas d'unicité inter-fichiers), unicité des
     noms par fichier, terrain valide, ligne malformée
     → erreur explicite (crash au démarrage si invalide)
   - expose :
       type Asset struct { Code string; Name string }
        type Qualificatif struct { Prefix string; Name string; Terrain string }
       type Assets struct {
           Communes, Prenoms []Asset
           Qualificatifs []Qualificatif
       }
       func Load(dir string) (Assets, error)

4. Tests unitaires : chargement depuis assets/ réel (invariants OK), détection
   d'un doublon et d'un CSV malformé (fichiers temporaires en test).

5. Intègre le chargement au démarrage de cmd/server (log des compteurs ;
   échec = crash explicite).

Critères d'acceptation :
- make test passe (loader + invariants vérifiés)
- make run logue les compteurs d'assets au démarrage
- Tous les trigrammes font exactement 3 lettres ; tous les prefixes font
  1 lettre ; tous les terrains font partie de la liste autorisée
  (plain|forest|hill|mountain|swamp|any) ; pas de doublon de code ni de nom
  au sein d'un même fichier

Note : les noms et codes de TERRITOIRES ne sont PAS dans les assets : ils sont
générés à la carte (P1.2) à partir des qualificatifs et des communes adjacentes.

Ne commite pas : je m'en charge.
```
