# Plan P0.1 — Squelette repo Go (à déléguer)

Brief d'exécution autonome pour un modèle d'implémentation.

## Contexte

Repo neuf contenant uniquement `specs/`, `LICENSE`, `.opencode/`. Le prompt source
est `specs/prompts/p0.1-squelette-repo.md` — le lire en entier avant de commencer.

Règle absolue : code exclusivement en anglais (identifiants, commentaires, logs).
Ne rien commiter (l'utilisateur s'en charge).

## Difficulté et modèle recommandé

Difficulté 1/5 — scaffolding boilerplate entièrement spécifié. Modèle budget
conseillé : DeepSeek V3.x (`deepseek/deepseek-chat`) — coût estimé < 0,02 €.
Alternatives équivalentes : Kimi K2, Qwen3 Coder, GLM-4.6.

## Étape 0 — Outillage (guider l'utilisateur, en arrière-plan)

Go et Docker ne sont pas installés. Fournir à l'utilisateur ces commandes à
exécuter (sudo requis), puis continuer l'étape 1 pendant l'installation :

```bash
sudo apt update && sudo apt install -y golang-go docker.io
sudo usermod -aG docker $USER   # puis newgrp docker ou re-login pour docker sans sudo
```

Avant l'étape 2, vérifier : `go version` ≥ 1.22 et `docker version`.

## Étape 1 — Fichiers à créer (12)

### 1. `go.mod`

`module github.com/fogfactory/crown-and-borough` + directive `go 1.22`.
Zéro dépendance tierce.

### 2. `cmd/server/main.go`

Stdlib uniquement (`net/http`). Mux via constructeur nommé (ex. `newServer()`)
pour testabilité, route `GET /healthz` → 200 (pattern de méthode Go 1.22).
Port : env `PORT`, défaut `8080` (justification : Cloud Run injecte `PORT`,
cf. roadmap P3.5). Log de démarrage en anglais.

### 3. `cmd/server/main_test.go`

Test trivial : `httptest.NewRecorder` + requête `GET /healthz` → assert status 200.

### 4. Dossiers vides + `.gitkeep`

`internal/api/`, `internal/engine/`, `internal/db/`, `internal/models/`,
`assets/` reçoivent chacun un `.gitkeep` (git ne suit pas les dossiers vides).
Ne PAS créer `internal/server/` (prévu au palier P3, hors scope du prompt).

### 5. `web/README.md`

Placeholder indiquant que le front React/Vite arrive en P0.3.

### 6. `Makefile`

`.PHONY` + cibles :

- `build` : `go build -o bin/server ./cmd/server`
- `run` : dépend de `build`, exécute `./bin/server`
- `test` : `go test ./...`
- `vet` : `go vet ./...`
- `clean` : `rm -rf bin`

### 7. `Dockerfile`

Multi-stage :

- Stage build : `FROM golang:1.26-alpine AS build` (variante épinglée de
  `golang:alpine` pour la reproductibilité), `WORKDIR /app`, `COPY go.mod ./`,
  `COPY . .`, commentaire clair réservant l'emplacement de la future étape de
  build front (`web/`, tâches P0.3/P3.5), puis
  `RUN CGO_ENABLED=0 GOOS=linux go build -trimpath -ldflags="-s -w" -o /out/server ./cmd/server`
- Stage final : `FROM scratch` (binaire statique, pas de TLS sortant au MVP →
  pas besoin de CA certs), `COPY --from=build /out/server /server`,
  `EXPOSE 8080`, `ENTRYPOINT ["/server"]`

### 8. `.dockerignore`

`.git`, `bin`, `specs`, `web/node_modules` (garde le contexte de build propre).

### 9. `.github/workflows/ci.yml`

Déclencheur push/PR vers `main`, deux jobs :

- `go` : `actions/checkout@v4` + `actions/setup-go@v5` (version lue depuis
  `go.mod`) → `go vet ./...` → `go test ./...` → `go build ./...`
- `docker` : `docker build -t crown-and-borough .` (build seul, pas de push)

Actions officielles uniquement.

### 10. `.gitignore`

Go (`bin/`, `*.test`, `*.out`) + Node (`node_modules/`, `dist/`) + `.env` +
fichiers OS.

## Étape 2 — Vérification (critères d'acceptation)

| # | Commande | Attendu |
|---|---|---|
| 1 | `make vet` | vert |
| 2 | `make test` | vert (≥ 1 test healthcheck) |
| 3 | `make build` | `bin/server` exécutable produit |
| 4 | `make run &` puis `curl -i localhost:8080/healthz` | HTTP 200 |
| 5 | `docker build -t crown-and-borough .` | build vert, image finale ~15 Mo (`docker images`) |
| 6 | `docker run --rm -p 8080:8080 crown-and-borough` + curl | 200 dans le conteneur |
| 7 | `go list -m all` | aucune dépendance tierce |
