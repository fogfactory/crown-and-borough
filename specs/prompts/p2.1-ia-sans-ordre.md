# Prompt P2.1 — Armées "Sans Ordre" : soutien défensif automatique

```
Tu travailles sur "Crown & Borough", un jeu de stratégie asynchrone par tours.
Le moteur de résolution existe (P1.4, internal/engine : phases 0-5 — intentions,
soutiens, itération, exécution, progression — avec la phase 0 ravitaillement de
P1.5), les modèles (P1.1), le parser (P1.3), balance.json (P1.6).
Références : specs/gdd.md (§6 Armées "Sans Ordre" — IA Défensive
Auto-équilibrée) et specs/architecture.md (§6 — armée sans chaîne).

PÉRIMÈTRE : soutien défensif automatique des armées SANS CHAÎNE (Sans Ordre).
Vision T0 (P2.2) et transmission différée (P2.3) HORS périmètre.

RÈGLE DE CODE : code EXCLUSIVEMENT en anglais (identifiants, commentaires,
messages, enums). Seules les chaînes de contenu de jeu sont en français.

1. RÈGLE (GDD §6) : une armée Sans Ordre (aucune chaîne, army.chain == nil)
   apporte son soutien à l'armée alliée la plus proche qui possède le moins
   de soutien, stabilisant automatiquement la ligne de front.

2. INTÉGRATION au moteur (internal/engine, dans Resolve) :
   - Calculée APRÈS la Phase 1 (intentions) et FONDU DANS la Phase 2
     (soutiens) : les soutiens automatiques participent à la même itération
     (Phase 3) que les ordres S — mêmes règles de coupure et de puissance
   - DÉTERMINISTE : armées Sans Ordre traitées par matricule CROISSANT ;
     BFS par ID croissant

3. SÉLECTION DE LA CIBLE :
   - Candidats = armées ALLIÉES (même joueur) ENGAGÉES dans un combat ce
     tour : soit elles attaquent une case contestée, soit leur case est
     contestée par une attaque ennemie (défense). Une armée sans combat
     possible n'est jamais ciblée
   - Pour chaque armée Sans Ordre (matricule croissant) :
       1. la candidate la PLUS PROCHE (distance BFS dans le graphe des
          territoires, départage : ID croissant)
       2. départage : la candidate au MOINS DE SOUTIEN (compteur = ordres
          S reçus + soutiens automatiques déjà assignés ce tour)
       3. départage final : matricule de la candidate croissant
     Après sélection, le compteur de soutien de la candidate est
     INCRÉMENTÉ (les armées Sans Ordre suivantes voient les choix déjà
     faits)
   - Aucun candidat (aucun combat allié) → l'armée Sans Ordre ne soutient
     pas (inactive ce tour)

4. PUISSANCE ET SÉMANTIQUE :
   - Puissance : 1 PAR ARMÉE Sans Ordre (choix documenté : l'unité du
     soutien automatique est l'armée, pas la pile — contrairement à l'ordre
     S dont la puissance = taille de la pile)
   - Effet : comme un ordre S — +puissance à la force d'attaque de la cible
     si elle attaque, +puissance à sa défense si elle tient
   - COUPURE : le soutien automatique d'une armée est coupé si la PILE de
     cette armée est elle-même attaquée ce tour (même règle que S)
   - Une armée Sans Ordre qui soutient n'émet AUCUN mouvement (elle reste
     sur place) et ne change pas d'état (elle reste Sans Ordre, chaîne nil)

5. EVENTS : Resolution reçoit une liste AutoSupports (armée soutenante,
   cible, puissance, coupé ?) — utilisée par le TurnReport (P1.7) dans la
   section combats (soutiens) ; pas de formatage ici

6. TESTS (internal/engine/autosupport_test.go) :
   - Ligne de front : 2 alliés tiennent des cases adjacentes, l'ennemi
     attaque l'un des deux → l'armée Sans Ordre soutient SA défense (+1) et
     l'allié tient (à égalité 1+1 vs 1)
   - Attaque : la cible Sans Ordre soutient un allié qui ATTAQUE (+1 à sa
     force d'attaque)
   - Le plus PROCHE : deux alliés engagés à des distances différentes → la
     cible la plus proche est soutenue
   - Le MOINS SOUTENU : deux alliés à égale distance, l'un déjà soutenu par
     un ordre S → l'armée Sans Ordre soutient l'AUTRE ; deux armées Sans
     Ordre successives → la 1re prend le moins soutenu, la 2e voit le
     compteur mis à jour et équilibre
   - COUPURE : la pile d'une armée Sans Ordre est attaquée → son soutien
     est annulé dans la résolution
   - Pas de combat allié → aucune armée Sans Ordre ne soutient
   - Soutien automatique sans ordre S : puissance = 1 même si la pile de
     l'armée Sans Ordre contient N armées (N armées Sans Ordre = N×1)
   - DÉTERMINISME : deux appels Resolve sur le même état → mêmes soutiens
     automatiques (état final + événements identiques) ; cohérence (les
     cibles sont bien des armées alliées engagées)

Critères d'acceptation :
- make test passe ; make vet passe ; aucune dépendance tierce ajoutée
- Le code existant de Resolve (phases 1, 3, 4, 5) n'est pas modifié : le
  soutien automatique s'insère dans la phase 2 (ou une sous-phase dédiée
  appelée par phase 2)
- Resolve reste pure et déterministe

Note : documente dans ta réponse finale les choix ouverts que tu as tranchés
(puissance 1/armée, candidats = armées engagées uniquement, distance comme
critère principal puis moindre soutien, compteurs dynamiques) pour mise à
jour des specs (ne modifie pas les specs toi-même). Ne commite pas : je m'en
charge.
```
