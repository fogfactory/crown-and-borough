# Plan P1.8 — Interaction et lisibilité de la carte

## Décision d'interaction

Le geste de déplacement ne nécessite pas de modificateur clavier : un clic
gauche est d'abord traité comme un clic candidat. Si le déplacement dépasse le
seuil anti-drag existant, le geste devient un pan et la sélection candidate est
abandonnée. Un relâchement sans dépassement du seuil sélectionne le territoire,
le désélectionne s'il était déjà sélectionné, ou efface la sélection si le fond
SVG était visé. Les gestes tactiles de déplacement restent pris en charge.

## Fichiers concernés

- `web/src/components/MapViewer.tsx` — machine d'interaction, callback nullable,
  `clipPath` SVG et lisérés.
- `web/src/App.tsx` — texte d'aide de la carte.
- `web/README.md` — documentation des gestes.
- `web/package.json` et `web/package-lock.json` — outillage de tests frontend.
- `web/vite.config.ts` — configuration Vitest.
- `web/src/test/setup.ts` — adaptations jsdom pour les API SVG nécessaires.
- `web/src/components/MapViewer.test.tsx` — tests d'interaction et de rendu.
- `specs/prompts/p1.8-interaction-lisibilite-carte.md` — décision clic/drag.
- `specs/roadmap.md` — transitions de statut P1.8.

## Étapes

1. Étendre `onSelect` pour accepter `string | null` et centraliser la bascule
   de sélection, y compris le clavier et le fond SVG.
2. Conserver le `pointer capture`, le calcul de coordonnées, le seuil de 4 px,
   l'annulation et la molette, mais transformer un pointer gauche dépassant le
   seuil en pan sans déclencher de sélection.
3. Définir un `clipPath` par territoire dans le groupe transformé de la carte.
   Dessiner les traits de contrôle et de sélection en `fill="none"`, avec une
   largeur suffisante pour que la moitié visible soit intérieure au polygone.
4. Placer les lisérés avant les frontières afin que les traits continus et
   pointillés soient toujours rendus au-dessus. Supprimer uniquement le
   remplissage de contrôle ; le rendu de fraîcheur existant reste hors du
   périmètre P1.8.
5. Mettre à jour l'aide visible, la légende et la README.
6. Ajouter les tests Vitest/jsdom couvrant le clic, la bascule, le fond, le
   clavier, le drag et les attributs SVG de contrôle/sélection.
7. Exécuter les tests, le build et le lint, puis vérifier manuellement les
   frontières partagées et les gestes dans le navigateur.

## Validation

- `npm run test` depuis `web/`.
- `npm run build` depuis `web/`.
- `npm run lint` depuis `web/`.
- Contrôle manuel d'une frontière entre deux joueurs, d'une frontière
  franchissable et d'une frontière infranchissable.
- Contrôle manuel du zoom, du pan par maintien-déplacement, des gestes tactiles
  et de la sélection au clavier.

## Risques

- Les API `getBoundingClientRect` et pointer capture doivent être simulées dans
  jsdom.
- Les `clipPath` doivent être définis dans le même espace de coordonnées que le
  groupe `translate/scale`, sinon le rendu peut être décalé malgré un build
  valide.
- Le voile de données anciennes reste volontairement inchangé ; les pois de
  fraîcheur sont reportés à P2.2/P3.4.

## Difficulté et modèle recommandé

**Difficulté : 3/5 (intermédiaire).** Le changement reste local au frontend,
mais combine une machine clic/drag sensible aux événements pointer, un rendu
SVG avec découpage géométrique et l'ajout d'un outillage de tests absent du
projet.

**Implémentation recommandée :** `openrouter/openai/gpt-5.6-luna`.

**Revue obligatoire :** `openrouter/moonshotai/kimi-k3`, avec une attention
particulière portée aux transitions pointer, au support tactile, aux
coordonnées des `clipPath` et aux tests manquants.
