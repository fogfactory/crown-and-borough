# Prompt P1.4 — Moteur de résolution : intentions, combats, retraites, progression

```
Tu travailles sur "Crown & Borough", un jeu de stratégie asynchrone par tours.
Le parser et les modèles d'ordres/chaînes existent (P1.3, internal/models +
package de parsing), la génération de carte est en place (internal/engine/mapgen).
Références : specs/gdd.md (§5 Combats, §6 Retraites, §8 Contrôle territorial)
et specs/architecture.md (§6 — sémantique des ordres, à suivre à la lettre).

PRINCIPE FONDAMENTAL : on ne sépare PAS les déplacements des combats. La
résolution est de type Diplomacy : on énumère d'abord TOUTES les intentions
(qui veut aller où, avec quelle puissance), on calcule les soutiens, on
ITÈRE jusqu'à stabilité, et seulement ensuite on exécute les mouvements.

PÉRIMÈTRE : résolution simultanée des ordres de TOUTES les chaînes, combats,
retraites, contrôle territorial, progression des chaînes. RAVITAILLEMENT/
famine (P1.5), HIVER (P1.6) et transmission différée (P2) HORS périmètre
(vision T0) : le moteur est conçu en phases pour s'y brancher.

RÈGLE DE CODE : code EXCLUSIVEMENT en anglais (identifiants, commentaires,
messages, enums). Seules les chaînes de contenu de jeu sont en français.

1. Interface (internal/engine) :
   - Resolve(game *models.GameState) (Resolution, error) — fonction PURE,
     déterministe, sans I/O
   - Resolution : EVENTS structurés (outcomes par ordre, combats, retraites,
     fusions, pillages, dispersions, changements de contrôle) que P1.7
     formatera en TurnReport — pas de formatage ici
   - Architecture en PHASES :
       Phase 1 — Énumération des intentions (mouvements et puissances)
       Phase 2 — Calcul des soutiens
       Phase 3 — Itération de résolution jusqu'à stabilité (combats)
       Phase 4 — Exécution des mouvements + retraites
       Phase 5 — Progression des chaînes + contrôle territorial
     Points d'extension clairs pour ravitaillement (P1.5) et propagation
     (P2). Itération DÉTERMINISTE : troupes par matricule croissant,
     territoires par ID.

2. Phase 1 — Intentions : pour chaque territoire, lister les ARMÉES qui
   veulent s'y rendre selon l'ordre courant de leur chaîne (les ordres
   s'appliquent aux ARMÉES — jamais d'ordres mixtes au sein d'une armée) :
   - A (attaque/atteindre) : intention de déplacement CONTESTÉE ; chaque
     armée attaquante est un contendant distinct — puissance = TAILLE de
     l'armée ; les attaques d'armées d'origines DIFFÉRENTES ne se combinent
     PAS (il faut un soutien S pour cumuler) — y compris entre armées du
     MÊME joueur (deux armées convergeant par A sur une même case se
     disputent : comparaison des contendents, cf. Phase 3)
   - J (jonction) / D (dispersion) : déplacements PACIFIQUES, puissance 0
     (ils ne contestent pas la case)
   - H / P / S : pas de mouvement (reste, pillage, soutien)
   - Position exigée : troupe absente de la position de l'ordre → failure
     (pas d'intention émise)

3. Phase 2 — Soutiens : chaque ordre S de l'armée P (PUISSANCE = TAILLE DE
   L'ARMÉE P) est EXPLICITE et vise une armée désignée, de TOUTE NATIONALITÉ
   (on peut soutenir un autre joueur, même contre soi) :
   - OFFENSIF `XXX S YYY - ZZZ` : si l'armée en YYY ATTAQUE ZZZ ce tour, le
     soutien s'ajoute à SA force d'attaque ; sinon (armée absente, n'attaque
     pas ZZZ) → SANS EFFET (gaspillé, mais l'ordre réussit — cf. Phase 5)
   - DÉFENSIF `XXX S YYY` : si l'armée en YYY TIENT (ordre sans
     déplacement : H, S ou P), le soutien s'ajoute à SA défense ; si elle
     se déplace (A/J/D) ou est absente → SANS EFFET (gaspillé, mais réussit)
   - COUPURE (règle Diplomacy) : le soutien de P est ANNULÉ si P est
     attaquée ce tour DEPUIS UNE CASE DIFFÉRENTE de celle vers laquelle
     elle soutient (ZZZ en offensif, YYY en défensif) — une attaque venue
     de cette case-là ne coupe PAS le soutien

4. Phase 3 — Itération jusqu'à stabilité (manière Diplomacy) :
   Répéter jusqu'à ce que plus rien ne change (fixé) :
   a. Forces d'attaque : pour chaque ARMÉE attaquante, force = taille de
      l'armée + soutiens offensifs non coupés désignant CETTE attaque
      (Phase 2). Les attaques d'armées d'origines DIFFÉRENTES sont des
      contendents DISTINCTS, même alliés ou du même joueur : elles ne
      s'additionnent jamais
   b. Forces de défense : force = taille de l'armée occupant la case +
      château +1 (si présent, MÊME SANS garnison : une case-château n'est
      jamais vide pour un attaquant) + soutiens défensifs non coupés
   c. Coupure des soutiens : les soutiens des armées attaquées depuis une
      case DIFFÉRENTE de celle vers laquelle elles soutiennent sont
      annulés (règle Diplomacy, Phase 2)
   d. Résolution des cases contestées : comparaison unique de toutes les
      forces (chaque armée attaquante + la défense) ; la force STRICTEMENT
      la plus haute l'emporte ; TOUTE égalité au sommet → statu quo
      (défense tient, tous les attaquants échouent, leurs A sont des
      failures) — y compris entre attaques alliées ou du même joueur (ex.
      deux attaques de 1 contre une défense de 1 : statu quo ; pour
      prendre, une attaque SOUTENUE par un S offensif : 1 + 1 > 1) ; sur
      case VIDE convergent plusieurs armées (même joueur inclus) : la plus
      grosse entre, les autres restent ; égalité au sommet → toutes restent
   e. Les J/D vers une case contestée par une attaque ce tour sont
      REPOUSSÉS (bounce, failure), quel que soit le résultat de l'attaque
   f. Une armée dont la case est PRISE est DÉLOGÉE : son propre ordre de
      mouvement est ANNULÉ (failure) — elle battra en retraite (Phase 4) ;
      si la case tient, son mouvement s'exécute normalement
   - A vers une case occupée par un ALLIÉ : failure (pas d'attaque d'allié)
   - A vers une case VIDE (aucune autre armée n'y converge) : succès direct
     (pas de combat)

5. Phase 4 — Exécution des mouvements et retraites :
   - Les attaquants gagnants occupent la case conquise ; les attaquants
     perdants restent sur place ; les J/D repoussés restent sur place ;
     une armée DÉLOGÉE (sa case est prise) voit son mouvement annulé et
     part en retraite
   - Fusion (jonction J UNIQUEMENT — deux armées convergeant par A ne
     fusionnent PAS, cf. Phase 3d) : la jonctionnante fusionne si une armée
     alliée est déjà sur la case, OU si exactement UNE autre armée alliée y
     arrive au même tour (par A ou J) sans autre convergence ; l'armée
     fusionnée conserve la chaîne de l'HÔTE (armée en place, ou l'arrivant
     par A) — celle de la jonctionnante est de toute façon consommée, J
     étant toujours le dernier ordre ; J+J : les deux chaînes étant
     consommées, l'armée fusionnée est SANS ORDRE ; J vers une case avec
     convergence de plusieurs troupes → REPOUSSÉ (échec) ; deux armées qui
     se CROISENT (chacune jonctionne vers la case de l'autre) arrivent
     SANS fusionner
- P (pillage) : cible = la case de la troupe ; détruit l'infrastructure de la
      case (une seule par case — « Règle de la Structure Unique », GDD §3) +
      bonus R (balance.json, défaut : 2) CRÉDITÉ AU
     LIEU-DIT CONTRÔLÉ LE PLUS PROCHE du joueur (BFS, départage trigramme ;
     perdu s'il n'en contrôle aucun) ; aucune infrastructure → invalid
   - D (dispersion) : les destinations libres et non contestées sont
     rejointes ; la troupe d'origine (porteuse de la chaîne) prend la
     PREMIÈRE destination listée ; les autres troupes sont CRÉÉES (matricule
     suivant — compteur dans GameState si nécessaire, documente) ; toute
     destination non résolue → ordre non résolu intégralement
   - NOBLES — chevauchée (GDD §6) : après les mouvements, les nobles de
     chaque case suivent les troupes :
       * armée qui se déplace en bloc (A/J/retraite vers une même
         destination) → le noble la suit
       * D : répartition par ASTÉRISQUE (parser P1.3) — `*` seul = tous les
         nobles restants, `*CODE` = noble désigné (chaque noble au plus une
         fois) ; TOUS les nobles qui chevauchent l'armée (y compris les
         prisonniers) doivent être assignés, sinon l'ordre est INVALIDE
         (aucune troupe d'origine par défaut — GDD §6)
        * PRISONNIER : un noble prisonnier suit les mêmes règles de chevauchée
         (il se déplace avec l'armée qui le détient, selon les ordres du
         joueur de cette armée)
   - NOBLES — capture (GDD §6) : si l'armée que chevauche un noble est
     DÉTRUITE (pas de retraite possible ou collision de repli) ET qu'une
     troupe ENNEMIE occupe sa case → le noble devient PRISONNIER de ce joueur
     (LocationID = la case, statut prisoner) ; récupéré par l'armée
     gagnante ; armée détruite sur case vide/alliée → le noble reste sur
     place (non capturé, cas limite toléré) ; le noble n'est jamais détruit
     ni compté dans les forces ni dans le ravitaillement
    - RETRAITES (GDD §6) : une armée battue se replie EN BLOC vers une case
      adjacente valide (non occupée, non ciblée par un combat ce tour,
      différente de la case d'origine de l'attaquant). Traitement par
      matricule croissant : première case valide par ordre d'ID EN ÉVITANT
      une case déjà choisie par une retraite précédente si une alternative
      existe ; deux armées vers la même case SANS autre option → les deux
      DÉTRUITES (la double destruction n'a lieu qu'en l'absence
      d'alternative — GDD §6) ; aucune case valide → DÉTRUITE

6. Phase 5 — Progression des chaînes et contrôle territorial :
   - Par ordre exécuté, outcome ∈ { success, failure, invalid } :
     - success → CurrentIndex++ (chaîne consommée si dernier ordre, armée
       Sans Ordre)
     - failure → single : chaîne BRISÉE (armée Sans Ordre) ; loop : index
       inchangé (retentative au tour suivant)
     - invalid → chaîne BRISÉE dans les deux modes
   - Boucle de veille : H en loop = garde indéfinie (index figé) ; J en
     loop = retente jusqu'à réussite, puis chaîne consommée (J est toujours
     le dernier ordre)
- S en LOOP : offensif — index INCHANGÉ tant que l'armée de YYY attaque
      ZZZ, avance sinon ; défensif — index INCHANGÉ tant que YYY est
      attaquée, avance sinon
   - Boucle "coincée" (position devenue inaccessible) : retente
     indéfiniment — comportement attendu, le joueur remplace la chaîne
   - CONTRÔLE TERRITORIAL (GDD §8) : toute case occupée en fin de résolution
     (arrivée, fusion, conquête) bascule sous le contrôle du propriétaire
     des troupes qui l'occupent (TerritoryState.OwnerID) ; rémanence : le
     contrôle persiste après le départ des troupes, jusqu'au passage d'un
     ennemi

7. Tests (internal/engine/resolve_test.go, scénarios exhaustifs) :
   - Mouvement : case vide (succès + contrôle), case alliée (failure A),
     position manquante (failure), J/D repoussés sur case contestée
- Combat : égalité = statu quo ; supériorité = victoire + retraite ;
       défenseur sans case valide = détruit ; collision de repli SANS
       alternative = les deux détruits, AVEC alternative = la 2e armée évite
       la case ; soutien OFFENSIF décisif (+armée à l'attaque désignée, y
       compris celle d'un AUTRE joueur) ; soutien DÉFENSIF (+armée à la
       tenue d'une armée en H/S/P) ; soutien VOID (armée absente, n'attaque
       pas ZZZ, ou se déplace → gaspillé mais réussi) ; soutien COUPÉ
       (attaque depuis une case ≠ celle soutenue) ; soutien NON coupé
       (attaque depuis la case soutenue) ; château +1, y compris SANS
       garnison (une case-château n'est pas vide) ; armée de N = force N
       (contendant unique) ; deux attaques d'armées distinctes = contendents
       séparés (1+1 vs 1 → statu quo) ; attaque SOUTENUE (1+1) vs 1 →
       victoire ; deux armées du MÊME joueur convergeant par A sur case vide
       = standoff (plus grosse entre / égalité → statu quo) ;
       multi-attaquants ennemis (conflit, égalité — case vide incluse) ;
       armée DÉLOGÉE = mouvement annulé + retraite ; itération stable (deux
       passes identiques)
     - J : fusion avec allié présent (chaîne de l'hôte conservée, celle de
       la jonctionnante consommée) ; fusion avec allié arrivé par A sans
       contestation (chaîne de l'arrivant conservée) ; J+J → fusion, armée
       Sans Ordre ; J vers case contestée ou à convergence multiple →
       repoussé ; croisement J↔J (échange de cases) → arrivées sans fusion ;
       ennemi = failure
    - D : intégrale vs partielle (single avance, loop retente) ; destination
      attaquée ; chaîne suit la troupe d'origine sur la 1re destination ;
      création de troupes avec matricules
   - P : infrastructure détruite + bonus R ; sans infrastructure = invalid
     (brise dans les deux modes)
- S loop : offensif — avance quand l'armée de YYY n'attaque plus ZZZ,
      index figé tant qu'elle attaque ; défensif — avance quand YYY n'est
      plus attaquée, index figé tant qu'elle l'est ; soutien void (armée
      absente ou action non conforme) = gaspillé mais réussi
    - Progression : single/loop/invalid appliqués sur chaînes MIXTES ;
      veille H/J ; chaîne consommée ; boucle coincée
    - Contrôle : conquête, rémanence après départ
     - Nobles : chevauchée avec une armée en bloc (A/J/retraite) ; répartition
       D par astérisque (`XXX*`, `YYY*JEA`, `YYY*JEA*ANN`) ; D avec nobles
       présents non tous assignés (ou sans astérisque) → ordre INVALIDE ;
       prisonnier qui suit son ravisseur ; CAPTURE : armée détruite (pas de
       retraite/collision) + ennemi sur la case → prisonnier du gagnant ;
       armée détruite sur case vide/alliée → pas de capture ; noble jamais
       détruit, jamais compté dans les forces
    - DÉTERMINISME : deux appels Resolve sur le même état → résultats
      identiques (état final + événements)
    - Cohérence de l'état retourné (troupes sur des territoires existants,
      armées cohérentes avec les fusions, compteur de matricules juste)

Critères d'acceptation :
- make test passe ; make vet passe ; aucune dépendance tierce ajoutée
- Resolve est pure, déterministe, sans I/O
- Les événements produits suffisent à construire un TurnReport (P1.7) sans
  accès à l'état interne
- Les phases sont identifiables pour insérer ravitaillement (P1.5) et
  propagation (P2) sans refactor majeur
```
