# Prompt P1.2d — Géométrie, frontières et graphe (rendu carte v2)

```
Tu travailles sur "Crown & Borough". P1.2a (vocabulaire), P1.2b (villages)
et P1.2c (nommage communes) sont faits. La génération de carte existe
(internal/engine/mapgen : raster 256x160, polygones, graphe avec routes,
config 1000x700 / 64 sites / ratio lieux-dits — désormais village), le
front (MapViewer) dessine les polygones et des ARCS pointillés
centroïde→centroïde pour les adjacences (web/src/components/MapViewer.tsx).
Références : specs/gdd.md (§3 Graphe franchissable), specs/roadmap.md
(P1.2 détaillé), specs/architecture.md (contrat map.json).

Tâche : refactor de la carte (géométrie + graphe + taille), suite à la
revue du rendu. Décisions actées :
- PLUS AUCUN territoire en bord de carte (les polygones tronqués au bord du
  viewport sont moche).
- Frontières DROITES avec un léger bruit pour faire naturel, plus d'escaliers.
- Contraintes d'interconnexion (degré max par terrain) à la place du système
  de routes ; les routes (arêtes non géométriques) SONT SUPPRIMÉES — c'est
  la cause du bug visuel observé (MBJL/RVBE adjacents sans frontière commune).
- ~8 territoires par joueur (SiteCount = 8 × nb joueurs).

RÈGLE DE CODE : code EXCLUSIVEMENT en anglais ; contenu de jeu en français.
Déterminisme : même seed → carte identique byte-for-byte.

1. PLUS DE TERRITOIRES DE BORD :
   - Mécanisme : ANNEAU de sites SACRIFIÉS. generateSites produit les
     SiteCount sites "intérieurs" (marge ~8 % de la plus petite dimension)
     PLUS un anneau de sites "cadre" placés près des bords du viewport
     (anneau fermé, jittered, densité ≈ espacement moyen des sites
     intérieurs). Le raster (assignRaster) est assigné SUR TOUT le
     viewport, sites intérieurs ET cadre confondus ; les polygones sont
     extraits pour tous ; SEULS les polygones des sites intérieurs sont
     conservés — les cellules du cadre (qui touchent les bords) sont
     REJETÉES et absorbent le bord. Un site intérieur, entouré de sites
     cadre du côté du bord, ne peut pas voir sa cellule Voronoï atteindre
     le bord du viewport.
   - Après extraction : RE-ANCRAGE avec PADDING explicite :
     * calcule la bbox minimale des polygones intérieurs (minX, minY,
       maxX, maxY) ;
     * translation : minX → padding, minY → padding (padding = constante
       documentée, p.ex. 2 % de la diagonale du viewport) ;
     * taille finale de la carte = maxX' + padding, maxY' + padding (le
       front dérive déjà mapWidth/mapHeight des points).
   - Contrainte absolue : AUCUN point de polygone à moins du padding du
     bord du viewport final (tous les territoires sont entièrement
     entourés d'un liseré, aucun n'est tronqué, aucun ne touche le bord —
     satisfiable par construction grâce au padding). La validation
     géométrique est adaptée (bornes = bbox + padding, plus des Width/
     Height fixes).
   - Les adjacences (géométriques et le graphe, §3) ne concernent QUE les
     sites intérieurs (les paires impliquant le cadre sont ignorées).
   - Le dev endpoint sert la carte générée telle quelle (le front
     s'adapte) ; specs/architecture.md : préciser que map.json ne transporte
     pas de taille explicite (le front la déduit des polygones).
   - Tests : aucun point de polygone à moins du padding du bord du viewport
     final ; nombre total de territoires = SiteCount ; déterminisme
     byte-for-byte.

2. FRONTIÈRES DROITES + BRUIT LÉGER :
   - Remplace la simplification actuelle (simple suppression de points
     collinéaires, qui laisse des escaliers) par une simplification de
     chaîne qui aplatit les marches : p.ex. Douglas-Peucker avec tolérance
     calibrée (≈ 3-4 cellules de la grille fine) appliqué sur les segments
     de la frontière de chaque polygone, ou méthode équivalente documentée.
     Résultat : frontières composées de segments LONGS et quasi-droits.
   - Cohérence des frontières partagées : un sommet de frontière commun à
     deux territoires doit rester EXACTEMENT le même point des deux côtés
     (les deux polygones partagent les mêmes sommets).
   - BRUIT : ajoute un léger jitter déterministe (seedé par les coordonnées
     du sommet de la grille fine d'origine, amplitude ≤ 1 % de la diagonale
     du viewport) aux sommets de frontières PARTAGÉS (communs à ≥ 2
     territoires), pour un rendu naturel sans marches. Le jitter est
     appliqué une seule fois par sommet partagé (identique pour les deux
     polygones voisins).
   - Tests : polygones valides (aire > 0, ≥ 3 points, dans la bbox) ; pas
     d'escalier résiduel : aucun sommet de frontière interne ne doit former
     des "marches" (critère : deux sommets consécutifs distants de moins de
     N cellules de grille fine, N documenté, doivent être rares/nuls — ou
     critère équivalent explicite) ; sommets partagés identiques des deux
     côtés ; déterminisme byte-for-byte.

3. GRAPHE SANS ROUTES, DEGRÉS CONTRAINTS PAR TERRAIN :
   - Supprime le système de routes : toute adjacence du graphe final est
     une ADJACENCE GÉOMÉTRIQUE (frontière partagée ≥ seuil existant
     minSharedEdges). Le graphe n'est plus augmenté d'arêtes non
     géométriques : repairGraphWithGeometry est remplacé (le code des
     routes est supprimé, y compris le fallback "complete geometric graph").
   - Contraintes de degré (sur le graphe final, adjacences franchissables) :
     * degré MINIMUM 2 partout (invariant existant conservé),
     * degré MAXIMUM par terrain du territoire :
       - mountain : 3
       - swamp : 3
       - hill : 3
       - plain : 5
       - forest : 5
   - Algorithme (déterministe, seedé) : part de TOUTES les adjacences
     géométriques, puis retire des arêtes en priorisant les paires
     "difficiles" (montagne/montagne, montagne/marais — forte probabilité
     de suppression, p.ex. 0.75, héritée de P1.2 ; les autres paires
     probabilité faible, p.ex. 0.15), SANS jamais casser la connexité ni
     passer sous le degré 2, puis réduit les degrés au-dessus du max en
     retirant des arêtes (priorité : paires difficiles puis les plus
     longues en distance de centroïdes), tant que connexité et degré ≥ 2
     sont préservés. L'invariant final : degré ∈ [2, max(terrain)] sur
     TOUT territoire, graphe connexe, symétrique.
   - Si un seed produit une configuration irréductible, l'erreur explicite
     existante est conservée (pattern actuel) — mais les tests doivent
     montrer que sur de nombreux seeds le générateur réussit.
   - BUG CORRIGÉ : plus aucune arête non géométrique (test dédié : chaque
     arête du graphe correspond à une paire partageant une frontière ≥
     minSharedEdges sur la grille — le cas MBJL/RVBE ne peut plus exister).
   - Tests : degrés dans les bornes par terrain sur ≥ 20 seeds ; connexité
     (BFS), symétrie, min 2 ; aucune arête non géométrique ; déterminisme.

4. TAILLE DE CARTE (~8 TERRITOIRES / JOUEUR) :
   - Constante moteur TerritoriesPerPlayer = 8 (documentée).
   - Endpoint dev GET /api/map : paramètre ?players=N (défaut 4, borné
     2..5) → SiteCount = 8 × players (défaut : 32) ; VillageCount =
     players + 1 (défaut : 5, cohérent avec P1.2b).
   - cmd/server : le handler passe de la génération unique au DÉMARRAGE à
     une génération À LA DEMANDE par (seed, players), avec un cache
     mémoire (clé = seed + players) pour ne régénérer que lorsque la clé
     change (le seed est fixe en dev, seul players varie — au plus 4
     variantes). Le log "map generated" a lieu au démarrage (pour le
     défaut players=4) et à chaque première génération d'une nouvelle clé.
     Validation des bornes : erreur 400 si players hors [2,5].
   - specs/architecture.md : documenter le paramètre dev.

5. FRONT (web/) — les arcs disparaissent, les frontières parlent :
   - Supprime le rendu des arcs centroïde→centroïde (AdjacencyArc).
   - Dessine les FRONTIÈRES partagées entre territoires voisins
     géométriquement (arêtes communes des polygones) :
     * frontière franchissable (présente dans adjacencies) : trait fin
       continu ;
     * frontière infranchissable (partagée géométriquement mais absente du
       graphe) : trait pointillé (ou autre distinction visuelle
       documentée) — elle reste visible pour la lisibilité du relief.
   - Légende mise à jour (remplace "Trait pointillé = adjacence
     franchissable").
   - npm run build && npm run lint.
```
