# Prompt P0.3 — Scaffold front + MapViewer v0

```
Tu travailles sur "Crown & Borough", un jeu de stratégie asynchrone par tours.
Le backend Go existe (cmd/server) et le front viendra se connecter à son API
plus tard (tâches P1.2/P1.7). Références : specs/architecture.md (section
Frontend et section "Contrats Serveur → Front : map.json / state.json") et
specs/gdd.md.

Tâche : créer le frontend dans web/ (Vite + React + TypeScript + Tailwind +
shadcn/ui) avec une première version du composant MapViewer.

RÈGLE DE CODE : le code est EXCLUSIVEMENT en anglais (identifiants, noms de
fichiers, commentaires, types). Seules les chaînes de contenu de jeu (noms de
communes, qualificatifs, labels UI affichés au joueur) sont en français,
langue du jeu.

DESIGN CLÉ : le front consomme DEUX documents JSON distincts :
- map.json : STATIQUE et constant (géographie publique : terrains, lieux-dits,
  polygones, adjacences) — identique pour tous les joueurs
- state.json : DYNAMIQUE (armées, infrastructures, contrôle, ressources) — c'est
  la vue d'un joueur, qui deviendra "stale" (vision T-x) en P2
Le front combine les deux au rendu. Cette séparation permet de rendre plusieurs
versions d'un même rapport (fraîcheur de l'information).

1. Scaffold dans web/ :
   - Vite + React + TypeScript (npm), Tailwind CSS (v4 via @tailwindcss/vite)
   - shadcn/ui initialisé (CLI), avec au moins les composants Button, Card,
     Select, Tooltip
   - ESLint/Prettier du template Vite conservés et fonctionnels

2. Fixtures (web/src/fixtures/) : deux fichiers distincts préfigurant le futur
   format API :
    - map.ts : ~12 territoires avec id, code (3 lettres pour un lieu-dit, 4
      sinon — ex. ROS, FROS), name, terrain, lieuDit, points (polygone simple
      dessiné à la main, pas encore de Voronoï) et adjacencies (graphe).
      Varier les 5 terrains, ~25 % de lieux-dits.
   - state.ts : une vue pour le joueur P1 : turn, season, asOf (fraîcheur par
     territoire, ex. { "T01": 0, "T02": 1 }), territories[{ id, owner,
     resources, armies[], infrastructures[] }], nobles[]. 2 joueurs (P1, P2)
     avec armées sur quelques territoires, quelques infrastructures (moulin,
     château) et 1-2 nobles.

3. Types (web/src/types.ts) : Territory, MapData, StateData, Army,
   Infrastructure, Noble, TerritoryState, alignés sur les fixtures et sur le
   contrat map.json/state.json de l'architecture doc.

4. Composant MapViewer (web/src/components/MapViewer.tsx) :
   - Props : { map: MapData; state: StateData; onSelect?: (id: string) => void }
   - Fond : un <path> SVG par territoire, coloré selon son terrain (palette :
     plaine = vert clair, foret = vert foncé, colline = marron, montagne =
     gris, marecage = bleu-vert) ; lieux-dits marqués d'un pictogramme
   - Couche vivante par-dessus : armées (petits marqueurs colorés par joueur),
     infrastructures (icône par type), ressources affichées sur les lieux-dits
   - Code (trigramme) au centre de chaque territoire, nom complet en tooltip
   - Pan/zoom souris (roulette = zoom centré curseur, drag = pan)
   - Clic sur territoire → sélection (contour surligné) + callback onSelect
   - Indication visuelle de la fraîcheur : territoire dont asOf < turn affiché
     avec un léger assombrissement/opacité (préparation de la vision T-x)
   - Légende des terrains dans une Card shadcn (flottante)

5. App.tsx : charge les deux fixtures, affiche MapViewer + un Card avec les
   infos du territoire sélectionné (code, nom, terrain, lieuDit, owner,
   resources, armées, infrastructures, fraîcheur asOf).

6. Makefile : ajouter une cible web-dev (cd web && npm run dev).

Critères d'acceptation :
- npm run dev (dans web/) : carte affichée (fond statique + couche dynamique
  superposées), zoom/drag fonctionnels, clic = sélection, tooltips, légende,
  marqueurs d'armées/infrastructures/nobles visibles
- La fraîcheur (asOf < turn) est visuellement distinguable
- npm run build passe sans erreur ni warning bloquant
- npm run lint passe
- make web-dev fonctionne depuis la racine
- MapViewer est générique : aucune dépendance aux fixtures (tout passe par
  les props map + state) — il sera branché sur l'API réelle plus tard

Ne commite pas : je m'en charge.
```
