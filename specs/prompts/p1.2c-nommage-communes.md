# Prompt P1.2c — Nommage : communes partout, affinité de terrain, trigrammes

```
Tu travailles sur "Crown & Borough". P1.2a (vocabulaire troupe/armée) et
P1.2b (lieux-dits → villages) sont faits. La génération de carte existe
(internal/engine/mapgen), le loader d'assets aussi (internal/db/assetgen,
assets/{communes,prenoms,qualificatifs}.csv), le contrat map.json est décrit
dans specs/architecture.md.
Références : specs/gdd.md (§3), specs/roadmap.md (P1.2 détaillé item 7),
specs/prompts/p0.2-assets-csv.md et p1.1-modeles-metier.md.

Tâche : nouveau nommage des territoires. Décisions actées :
- TOUT territoire porte un nom de commune (plus aucun "{Qualificatif} de
  {Commune}", plus de "Forêt de Rosemont", plus de "Vallées de...").
- Chaque commune est associée à un TERRAIN DE PRÉDILECTION : "Mont-Dore"
  n'est pas un nom de plaine. L'assignation favorise l'affinité, avec repli.
- Les codes de territoires sont des TRIGRAMMES partout (3 lettres), fini le
  schéma 3/4 lettres du lieu-dit.
- Le fichier qualificatifs.csv et son support dans le loader sont supprimés.

RÈGLE DE CODE : code EXCLUSIVEMENT en anglais ; contenu de jeu en français.

1. ASSETS (assets/communes.csv + loader) :
   - Nouveau format : code;nom;terrain — terrain ∈ {plain, forest, hill,
     mountain, swamp, any} ("any" = aucune affinité).
   - Étends le fichier d'environ 200 à 400-500 communes :
     * conserve les ~200 existantes en leur attribuant une affinité
       raisonnable (ex. Boisclair/Boisvert → forest, Belval/Belvent → any
       ou plain, etc.) ;
     * ajoute ~200-250 nouvelles, dont des composés médiévaux plausibles
       évoquant leur terrain de prédilection (ex. "Mont-Dore" → mountain,
       "Montsoreau" → mountain, "Beaupré" → plain, "Vergers" → plain,
       "Fougères" → swamp, "Bruyères" → hill, "Chênevaux" → forest…) ;
     * codes trigrammes uniques, noms uniques, chaque affinité de terrain
       représentée par plusieurs communes, "any" présent ;
     * SANS doublon de code ni de nom, tous les codes MAJUSCULES A-Z.
   - Loader internal/db/assetgen : struct Commune {Code, Name, Terrain},
     validation (terrain valide, unicité codes et noms, cohérence),
     suppression de Qualificatifs (struct, chargement, validation, tests) ;
     message de log du serveur (cmd/server) adapté ; SUPPRESSION du fichier
     assets/qualificatifs.csv.
   - Tests loader (p0.2) : nouveau format, invariants, présence d'au moins
     une commune par affinité + "any".

2. NOMNAGE MAPGEN (internal/engine/mapgen/naming.go) :
   - Chaque territoire reçoit le nom d'une commune de communes.csv :
     * priorité 1 : communes dont l'affinité == terrain du territoire ;
     * priorité 2 : communes "any" ;
     * repli : communes d'affinité différente si épuisées (déterministe,
       seedé).
   - Code du territoire = trigramme de la commune (3 lettres) ; unicité des
     codes sur toute la carte ; chaque commune utilisée au plus UNE fois ;
     contrainte : au moins une commune de chaque affinité de terrain utilisée
     si la carte contient ce terrain (le nommage doit rendre le terrain
     lisible : une montagne nommée "Mont-Dore" plutôt que "Belval").
   - Supprime isBorder() : avec la suppression du système de qualificatifs
     (ce prompt), le qualificatif "Marches" et sa condition de bord
     n'ont plus d'usage dans le nommage. (Note : les territoires de bord
     eux-mêmes ne disparaissent qu'en P1.2d — ici, seul le code de
     nommage lié à la bordure est nettoyé.)
   - Tests mapgen : tout territoire a un nom présent dans communes.csv ;
     ratio de territoires nommés par une commune "affine" (affinité ==
     terrain ou any) ≥ 0.90 sur plusieurs seeds ; codes 3 lettres,
     MAJUSCULES A-Z, uniques ; noms uniques par carte.

3. CONTRAT ET MODÈLES :
   - map.json : codes 3 lettres pour tous les territoires (contrat
     specs/architecture.md mis à jour).
   - internal/models : les invariants de code deviennent "3 lettres pour
     tout territoire" (modèles + tests, et mise à jour de
     specs/prompts/p1.1-modeles-metier.md).
   - Front : aucun changement de rendu requis (labels déjà affichés) —
     vérifie que rien ne dépend du préfixe 4 lettres (types, tri, tests).

4. RÉÉCRITURE DES DOCS (même dérogation que P1.2a/P1.2b, fichiers listés,
   substitution + reformulation minimale) :
   - specs/gdd.md §3 : nommage = nom de commune avec affinité de terrain
     (ex. "Mont-Dore" en montagne), trigramme comme code de territoire.
   - specs/roadmap.md : P1.2 détaillé item 7 (nommage) reformulé.
   - specs/prompts/p0.2-assets-csv.md : nouveau format communes.csv
     (colonne terrain), suppression de qualificatifs.csv.
   - specs/prompts/p1.1-modeles-metier.md : invariant des codes (3 lettres
     partout).
   - specs/prompts/p1.2-generation-carte.md : LAISSÉ TEL QUEL (historique).

5. Critères d'acceptation :
   - make test passe (loader + mapgen + modèles), make vet passe
   - make run : GET /api/map renvoie des noms de communes partout, codes
     3 lettres uniques, l'affinité terrain est visible (une montagne ne
     s'appelle pas "Beaupré" sauf repli, vérifiable sur le seed par défaut)
   - make web-dev : labels OK, aucune erreur console ; npm build/lint OK
   - assets/qualificatifs.csv supprimé ; aucune référence à Qualificatif
     dans le code

Note : documente dans ta réponse finale le nombre final de communes, la
répartition des affinités, et les replis observés sur le seed par défaut.
Ne commite pas : je m'en charge.
```
