# Plan P0.2 — Assets CSV + loader Go (à déléguer)

Brief d'exécution autonome pour un modèle d'implémentation.

## Contexte

Squelette P0.1 en place : `cmd/server` (mux `newServer()`, `GET /healthz`, port
via env `PORT`), `internal/{api,db,engine,models}` vides (`.gitkeep`),
`assets/` vide, Makefile (`build/run/test/vet/clean`), Dockerfile multi-stage
`FROM scratch`, Go 1.22, zéro dépendance tierce. Le prompt source est
`specs/prompts/p0.2-assets-csv.md` — le lire en entier avant de commencer.
Références : `specs/architecture.md` (§ Assets, lignes ~100-131 : format CSV,
convention de nommage) et `.opencode/AGENTS.md`.

Règles absolues :

- Code exclusivement en anglais ; seules les chaînes de contenu de jeu (noms
  de communes, prénoms, qualificatifs) sont en français.
- L'API exportée du loader est **dictée verbatim par le prompt** (y compris le
  type `Qualificatif` et les champs `Communes, Prenoms, Qualificatifs`) :
  c'est le contrat que P1.2 importe déjà (`assetgen.Assets`). Ne pas
  angliciser ces identifiants.
- Stdlib uniquement. Ne rien commiter.

## Difficulté et modèle recommandé

Difficulté **2/5** — le Go est trivial (~150 lignes, stdlib) ; l'essentiel du
travail est la **génération de contenu** : ~320 lignes CSV exigeant ~320
trigrammes uniques + discipline de format. Le risque (doublons, accents non
translittérés) est entièrement couvert par les tests du loader, qui servent de
boucle d'auto-vérification. Modèle conseillé : Kimi K2 (`moonshotai/kimi-k2`)
ou DeepSeek V3.x — coût estimé < 0,05 €. Un modèle budget suffit si l'on
insiste sur la vérification des unicités avant de clore.

## Étape 1 — `assets/communes.csv` (~200 lignes)

- En-tête `code;nom`, séparateur `;`, UTF-8, LF, pas de commentaires, pas de
  guillemets.
- Contenu : ~200 noms style lieux-dits français (Villeneuve, Rosemont,
  Griffecourt, Montauban, Valcroissant, Châteauneuf, Boisrond, Ferrières…).
  Varier les morphèmes (Ville-/Mont-/Roche-/Bois-/Val-/Pont- × -neuve/
  -mont/-court/-rière/-sur-…). Noms inventés mais plausibles, **uniques**,
  jamais vides.
- Codes : trigrammes stricts `^[A-Z]{3}$`. Translittération : É/È/Ê/Ë→E,
  À/Â→A, Ç→C, Î/Ï→I, Ô→O, Ù/Û→U, Ÿ→Y, Œ→OE. Dérivation : 3 premières
  lettres du nom normalisé (mnémotechnique) ; en cas de collision, variante
  mnémotechnique (1re+2e+4e lettre, squelette consonantique…). Unicité des
  codes et des noms **dans ce fichier**.
- Trier les lignes alphabétiquement par nom (maintenabilité, diffs propres).

## Étape 2 — `assets/prenoms.csv` (~120 lignes)

- Même format `code;nom`. ~120 **prénoms médiévaux français authentiques**,
  mixtes (Guillaume, Hugues, Amaury, Thibaut, Renaud, Eudes, Eustache,
  Bérenger, Mathilde, Adélaïde, Aliénor, Mahaut, Ysabeau, Béatrix…). Les
  accents restent dans la colonne `nom` ; les codes sont translittérés
  (Adélaïde → ADE).
- Mêmes règles d'unicité ; tri alphabétique.

## Étape 3 — `assets/qualificatifs.csv` (8-10 lignes)

- En-tête `prefix;qualificatif;terrain`. Ensemble proposé (préfixes uniques) :

| prefix | qualificatif | terrain |
|---|---|---|
| F | Forêt | forest |
| M | Monts | mountain |
| C | Collines | hill |
| P | Plaines | plain |
| A | Marais | swamp |
| H | Marches | any |
| B | Bois | forest |
| V | Vallées | hill |
| L | Landes | plain |
| R | Rochers | mountain |

- `terrain` ∈ `plain|forest|hill|mountain|swamp|any` ; **un seul `any`**
  (« Marches », réservé aux territoires de bordure en P1.2). Prefix = 1 lettre
  `A-Z`, unique.

## Étape 4 — Loader `internal/db/assetgen`

Nouveau package `internal/db/assetgen` (package `assetgen`), fichier
`assetgen.go`, stdlib (`encoding/csv`, `fmt`, `os`, `path/filepath`,
`strings`). API exportée **verbatim** :

```go
type Asset struct{ Code, Name string }
type Qualificatif struct{ Prefix, Name, Terrain string }
type Assets struct {
    Communes, Prenoms []Asset
    Qualificatifs     []Qualificatif
}
func Load(dir string) (Assets, error)
```

Comportement :

- Lit `communes.csv`, `prenoms.csv`, `qualificatifs.csv` dans `dir` ; fichier
  absent ou vide → erreur explicite.
- `csv.Reader` avec `Comma = ';'`, `FieldsPerRecord = 2` (3 pour
  qualificatifs) → les lignes malformées sont rejetées nativement avec n° de
  ligne.
- Saute la ligne d'en-tête ; `strings.TrimSpace` sur chaque champ.
- Validations par ligne, **fail-fast**, erreur
  `assetgen: <file>: line N: <reason>` (anglais) : code `^[A-Z]{3}$` (regex
  `MustCompile` ou vérif rune), nom non vide, prefix `^[A-Z]$`, terrain dans
  le set autorisé.
- Unicité par fichier via sets : codes, noms (par fichier d'assets), prefixes
  (qualificatifs). **Pas** d'unicité inter-fichiers.
- Doc de package en anglais.

## Étape 5 — Tests `internal/db/assetgen/assetgen_test.go`

- Helper `writeAssets(t, dir, communes, prenoms, quals string)` écrivant les
  3 CSV (versions minimales valides par défaut) dans `t.TempDir()`.
- `TestLoadRealAssets` : `Load("../../../assets")` sans erreur ; planchers
  `len(Communes) ≥ 180`, `len(Prenoms) ≥ 100`, `len(Qualificatifs) ≥ 8` ;
  ré-assert format de tous les codes/prefixes/terrains (garde-fou qualité
  données).
- Tests négatifs table-driven, chacun n'attend qu'une erreur non nil (et
  idéalement le nom du fichier dans le message) : doublon de code, doublon de
  nom, doublon de prefix, terrain invalide, ligne malformée (3 champs dans
  communes), code invalide (minuscules / 2 lettres / 4 lettres), nom vide,
  fichier manquant.

## Étape 6 — Intégration `cmd/server/main.go`

- `assetsDir := os.Getenv("ASSETS_DIR")`, défaut `"assets"` (même pattern que
  `PORT`).
- Au début de `main()`, avant `ListenAndServe` :
  `assets, err := assetgen.Load(assetsDir)` → `log.Fatalf("failed to load
  assets: %v", err)` si échec (crash explicite).
- Log des compteurs : `log.Printf("assets loaded from %s: %d communes, %d
  prenoms, %d qualificatifs", ...)`.
- `newServer()` et `/healthz` inchangés. `make run` depuis la racine → le
  chemin relatif `assets` résout correctement.

## Étape 7 — Dockerfile (fix de régression, validé)

Image `FROM scratch` : sans les assets, le conteneur crasherait au démarrage.
Ajouter après le `COPY` du binaire :

```dockerfile
COPY --from=build /app/assets /assets
ENV ASSETS_DIR=/assets
```

`.dockerignore` n'exclut pas `assets/` : rien d'autre à changer. `docker run`
redevient fonctionnel (critère P0.1 préservé).

## Étape 8 — Vérification (critères d'acceptation)

| 6 | `docker build -t crown-and-borough .` + `docker run --rm -p 8080:8080` + curl | 200, compteurs dans les logs |
